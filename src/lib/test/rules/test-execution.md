# 测试执行规范（步骤 5 · AI 实时驱动 Playwright）

**目标**：把已批准的测试用例**直接执行**——通过 Playwright MCP 浏览器工具实时驱动浏览器，逐条用例满足前置→执行操作→对照「预期结果」判定四态，捕获证据。**严禁在执行阶段修改任何业务源码与配置**。

> **V0.3 变更**：不再生成 `.spec.ts`、不再 `npx playwright test`。改为 AI 持浏览器工具实时操作被测系统，自判四态，落盘结构化结果。本规范同时被桌面应用的执行引擎注入到 AI 提示中。

**入口硬校验**：`/AI_LabTest/testCase/{模块}-testcase.md` 必须存在且非空，否则中断并退回步骤 4。

## 0. 环境预检（执行前强制）

### 0.0 范围边界（铁律）

| 环境 | 是否支持 | 说明 |
|---|---|---|
| **local** | ✅ 支持 | 本地开发环境 |
| **SIT** | ✅ 支持 | 集成测试环境 |
| **UAT** | ❌ **不支持** | 业务验收阶段，必须由业务方手工执行 |
| **生产（prod）** | ❌ **永不支持** | 自动化绝对不可触达生产 |

`environments.json` 的 `allowedEnvs` 字段是唯一可信白名单（默认 `["local", "sit"]`）。**禁止**对 `uat` / 生产 / 任何不在白名单的值执行。

### 0.1 目标环境（由平台指定，非交互）

**目标环境由平台在启动本步时指定**（见执行提示里的「环境：…」），直接使用。**本步为非交互运行，严禁用 `AskUserQuestion` 反问用户选环境**。仍然**禁止**对 `uat` / 生产 / 任何不在 `allowedEnvs` 白名单内的值执行；被指定为 UAT / 生产时拒绝并解释「UAT 由业务方负责、生产永不自动化」。

### 0.2 校验环境配置完整性（缺项不提问，引导去「设置 · 测试账号」）

读 `/AI_LabTest/environments.json`。**非交互运行：缺项一律不用 `AskUserQuestion` 反问用户**，改为把受影响用例判 `blocked` 并在结果/收尾总结里提示用户去「**设置 · 测试账号**」（项目环境配置）补齐后重跑：

| 字段 | 是否必须 | 缺失时行为 |
|---|---|---|
| `frontendBaseUrl` | 是 | 缺失 / `TBD` → 无被测地址，相关用例判 `blocked`，提示去「设置 · 测试账号」配置 |
| `apiBaseUrl` | 推荐 | 为 `TBD` → 仅警告，不阻塞 |
| 测试账号 / 登录态（`accounts`/`testAccount` / storageState） | 是（需登录的系统） | 缺失 / 失效 → 需登录的用例判 `blocked`，提示去「设置 · 测试账号」配置 / 重新捕获登录态；**绝不**手动登录，**更不**向用户索取凭证 |

**登录墙 / SSO / 401 处置**：访问被测系统被登录页拦住且无可用登录态时，不要手动登录、不要提问；判 `blocked` 并注明「未检测到登录态」。若整个系统都需登录（首个用例即被挡）→ 立即停止逐条空跑，其余用例一并 `blocked`，收尾明确提示用户去「设置 · 测试账号」配置登录态后重跑。

### 0.3 被测地址探活（强制）

对 `frontendBaseUrl` 做可达性探测（GET，有响应即视为站点在跑，含 3xx/4xx）：

| 结果 | 行为 |
|---|---|
| 可达 | ✅ 进入执行 |
| 连接被拒 / 超时 / DNS 失败 | ❌ **中断**，提示：local 请先启动前端服务 / SIT 请检查 VPN 与地址，**不要白跑一整轮**（不可达时每条用例都会失败且很慢） |

**探活次数上限（强制，防无限重试）**：最多探活 **3 次**（每次间隔≤2s）；**连续 3 次仍不可达 → 立即停止，不再重试、不执行任何用例**，直接提示用户「被测系统无法访问，请检查是否已正常启动 / 可访问」。**严禁无限重试 `curl`/请求探活**（会永不终止、刷屏，是明确缺陷）。

> 桌面应用的执行引擎会在**开跑前自动完成本探活**（连续 3 次不可达即拦下并提示用户，根本不进入本步），因此在桌面应用里执行时**无需**再用 `curl` 反复探活。仅当在目标项目里用 Claude CLI 独立执行（无引擎兜底）时，才由 AI 用 `curl`/请求工具完成探活，且**同样遵守上面的 3 次上限**。

### 0.4 选执行模式

| 模式 | 含义 |
|---|---|
| **可见（有头）** | 弹出可见浏览器窗口，操作过程肉眼可见，便于观察/演示 |
| **后台（无头）** | 不弹窗，仅产出四态结果，更快 |

用户未指定 → 默认后台无头。

## 1. 执行方式（用 Playwright MCP 浏览器工具）

执行**不依赖任何 spec 文件**。AI 用以下浏览器工具直接操作被测系统（工具名以 `browser_` 开头，由 Playwright MCP 提供）：

| 工具 | 用途 |
|---|---|
| `browser_navigate` | 打开/跳转页面（用 `frontendBaseUrl` 拼相对路径） |
| `browser_snapshot` | 读取页面可访问性结构（定位元素、确认真实状态的首选） |
| `browser_click` | 点击元素 |
| `browser_type` / `browser_fill_form` | 输入文本 / 批量填表 |
| `browser_select_option` | 下拉选择 |
| `browser_wait_for` | 等待文本出现/消失或超时 |
| `browser_take_screenshot` | 截图留证（保存到执行引擎指定的 output-dir） |
| `browser_start_video` / `browser_stop_video` | 录像起停（每条用例一段，命名 `{用例ID}.webm`，存到 output-dir） |
| `browser_network_requests` / `browser_network_request` | 列出网络请求 / 取单条完整方法·URL·状态码·请求体·响应体（失败用例采集接口信息） |
| `browser_navigate_back` / `browser_press_key` | 后退 / 键盘操作 |

**逐条用例的执行循环**：

1. 读测试用例的「前置条件 / 测试操作 / 预期结果 / 断言级别」。
2. 满足前置：需要登录态的用例，先用 `environments.json` 的账号在被测系统里登录建立会话；若前置卡在**非被测的第三方依赖**（如三方 OAuth 回调、验证码），按 §1.1 受控桩绕过，**真实登录优先、桩为兜底**。
3. **开录**：操作前 `browser_start_video({filename:"{用例ID}.webm"})` 开始录像。
4. 执行测试操作：按用例步骤在真实页面上操作；用 `browser_snapshot` 观察真实结构，不要凭空臆测元素。
5. 对照「预期结果」判定四态（见 §2）。
6. `browser_take_screenshot` 截一张图留证。
7. **失败采集接口**：fail / partial 用例用 `browser_network_requests` + `browser_network_request` 取关键请求的 方法/URL/状态码/请求体/响应体（请求体、响应体过长各截断 ≤4000 字符）。
8. **停录**：`browser_stop_video` 停止录像。**pass 用例录像不写进 evidence**（平台清理未引用录像）；**fail / partial 把 `{用例ID}.webm` 写进 evidence**。

**定位与判断纪律**：

- 元素定位以 `browser_snapshot` 的真实可访问性结构为准（角色/可见文本/标签），不要臆造选择器或文案。
- 断言对应真实可观察结果：可见文本、URL、元素出现/消失、列表条数等——以页面实际表现为准。
- 判定必须有真实证据（截图 / 快照 / URL）支撑，**不要为了变绿放水**。

## 1.1 受控网络桩（仅限非被测前置依赖）

Playwright MCP 已提供网络拦截工具，**默认不用**。仅当真实前置确实无法建立、且挡路的是「**非被测的外部 / 第三方依赖**」时，才允许受控桩，让被测核心路径得以建立——**目的是扫清前置障碍，绝不是制造假 pass**。

| 工具 | 用途 |
|---|---|
| `browser_route` | 按 URL pattern 拦截/桩网络请求（返回预设响应 / 放行 / 失败） |
| `browser_route_list` / `browser_unroute` | 查看 / 移除已设路由 |
| `browser_network_state_set` | 模拟离线/在线（仅供「断网」类用例断言，慎用） |

**黄金顺序（必须先真后桩）**：先尝试真实前置（真实登录、真实接口）→ 真实建立不起来 → 判断挡路依赖是否「非被测」→ 是则桩、否则 `blocked`。

**可桩（非被测前置依赖，示例非穷举）**：第三方 OAuth/SSO 登录回调、短信/邮件/图形验证码、地图/支付/统计/广告等第三方 SDK、与本用例被测功能无关的外部 API、CDN/字体等静态资源。

**绝不可桩（红线）**：

- 被测系统**自身的业务接口**——尤其本用例「预期结果」直接验证的那个接口；
- 用例断言依赖其返回数据的接口（桩了等于自己造答案）；
- 用 `browser_route` 把本会 `fail` / `blocked` 的结果改写成 `pass`。

**桩必留痕（强制）**：凡桩过的用例，`@@RESULT` 的 `actual` 必须写明「已桩 mock <依赖/URL>，理由：<非被测前置 / 外部依赖>」。被桩掉的部分**不计入验证**；被测断言仍按真实页面表现判四态——**桩只负责让前置成立，不负责让用例变绿**。

**用完即清**：用例结束用 `browser_unroute` 清掉本次路由，避免污染后续用例。

## 2. 四态判定决策树

**结果四态**：

| 状态 | 含义 |
|---|---|
| `pass` | 路径成立，预期可观察结果全部出现 |
| `fail` | 路径存在，但预期明确未出现且可复现（行为与预期相反，疑似应用缺陷） |
| `partial` | 部分断言已验证，另一部分被有意保留（用户拍板延后维度 / 用例被部分跳过） |
| `blocked` | 路径无法真实建立（前置 / 权限 / 数据 / 会话 / 外部依赖 / 地址不可达任一缺失）——**不是应用 bug** |

```
用例未通过
  ├─ 手动复现：UI 真的没按预期工作？
  │   ├─ 是 → 应用 bug → 判 fail，报告记录，不修源码
  │   └─ 否 ↓
  ├─ 路径根本无法建立？（必需字段/按钮/弹窗/账号/数据缺失，或外部依赖/地址未就绪）
  │   ├─ 是 → 挡路的是「非被测前置依赖」（第三方鉴权/验证码/外部SDK/无关外部API）？
  │   │        ├─ 是 → 按 §1.1 受控桩后重试；通了则继续判被测断言（桩须留痕、不算验证）
  │   │        └─ 否（被测接口/地址/账号本身缺失）→ blocked（判据：必需控件始终不可用 /
  │   │             页面不可达 / 必需账号或会话不可用 / 无法建立安全测试数据 / 被测地址不可达）
  │   └─ 否 ↓
  ├─ 仅部分维度被有意保留（用户已确认延后）？
  │   ├─ 是 → partial（备注「已验证 X，保留 Y，保留原因 Z」）
  │   └─ 否 ↓
  └─ flaky → 单次重试（≤1 次），仍不稳定按事实记录
```

**保持 fail（非 blocked）**：控件/页面/账号都存在但行为错——保存/提交/上传/导出/查询结果错误、展示错误数据、状态错误。
**重分类为 blocked**：必需控件始终不可用 / 页面不可达 / 必需账号或会话不可用 / 无法建立安全测试数据 / 缺外部依赖（**外部依赖若属非被测前置，先按 §1.1 受控桩；桩仍不通才 blocked**）。

### 2.1 意外状态恢复 → blocked 阈值

操作后到达预期之外的页面（错误页 / 首页 / 空白页）时：

1. 先 `browser_snapshot` 当前 URL + 关键元素，确认实际状态。
2. 已知场景按恢复路径处理：401 → 重新登录；导航错误 → `browser_navigate` 直跳目标；弹窗遮挡 → 先关闭再重试。
3. **连续 3 次仍无法恢复到预期状态 → 当前用例判 `blocked`**，备注记录恢复尝试。

**禁止**：无限重试 / 盲点其他按钮"自救" / 跳过预期断言直接判 pass。

### 2.2 整批鉴权熔断（401 雪崩）

执行中若**鉴权失败（401/登录态失效）的用例比例 > 50%**，立即停止剩余用例，整轮标 `CIRCUIT_BROKEN`。
典型根因：测试账号失效 / JWT 漂移 / DB `users` 表被清空 / 后端连不上 DB。处置：复测登录；失败则提示用户检查账号/环境，**不重跑**；成功视为 flaky 可重跑一次。

## 3. 失败处理铁律

### 3.1 严禁修改源代码

| 情况 | 允许动作 | 禁止动作 |
|------|---------|---------|
| 应用 bug（fail） | 报告中记录 + 三段式备注 | 修改 `src/`、`api/`、`components/` 等任何业务源码 |
| 环境问题 / blocked | 非被测前置依赖 → 按 §1.1 受控桩并在 `actual` 留痕；被测侧不可达 → 标注阻塞根因，等解除后重跑 | mock 被测接口 / 用桩把 `fail`·`blocked` 改写成假 `pass` / 桩了不留痕 |
| 需求未实现 | 标注失败并记录 | 自行实现该功能 |
| partial | 备注「已验证 X，保留 Y，原因 Z」 | 用 partial 掩盖未做的工作 / 不写保留原因 |

执行阶段**只在被测系统页面内操作**，只读测试用例/需求/环境与业务源码，绝不修改它们，也不改任何配置文件。

### 3.2 应用 bug 事实记录（仅事实，不给修复方案）

记录：测试用例 ID、重现步骤、预期、实际、证据（截图 / 录像路径）、接口信息（方法/URL/状态码/请求体/响应体，若有）。**禁止**写修复方案/改哪行/优先级/发布与否（属开发范畴）。

## 4. 执行产物（落盘契约）

逐条执行完成后，**落盘逐条结果**到 `/AI_LabTest/report/{模块}/{模块}-{ENV}.results.json`（严格 JSON，机读版；执行产物按模块分目录存放），执行引擎据此**确定性归约**四态计数：

```json
{
  "tests": [
    { "id": "TC-{模块}-001", "title": "用例标题", "status": "pass|fail|partial|blocked",
      "expected": "预期结果", "actual": "实际观察到的现象",
      "evidence": ["截图.png", "录像.webm（仅 fail/partial）"], "error": "失败/阻塞的简短原因（pass 留空）",
      "api": { "method": "POST", "url": "/api/...", "status": 200, "requestBody": "...", "responseBody": "..." } }
  ],
  "notes": "可选：整体说明"
}
```

引擎归约后产出 `/AI_LabTest/report/{模块}/{模块}-{ENV}.run.json`（四态计数 + 逐条状态 + 证据/熔断标记 + 执行时间）——这是**步骤 6 报告的唯一权威事实来源**。

- `status` 只用四态之一；其余值按 `fail` 计。
- 计数与通过率由引擎确定性计算，不要在结果里自报算术。

**导入导出文件留存**：测试页面的导入/导出功能时，相关文件统一留存到 `/AI_LabTest/report/{模块}/导入导出/`，供用户事后校对：
- **导出（下载）**：下载文件先落浏览器工具的 output-dir（证据目录），执行结束由引擎自动归档到上述目录；`actual` 里写明「已下载 <文件名>」。
- **导入（上传）**：上传所需的测试源文件先写入证据目录（文件名带用例 ID，如 `TC-{模块}-005-导入测试.csv`），再以绝对路径上传；执行结束同样自动归档。

## 5. 边界情况

| 场景 | 处理 |
|------|------|
| 整批因鉴权失效全失败 | 立即停止（§2.2 熔断），提示用户检查测试账号/环境 |
| 数据创建污染被测系统 | 用例内自行清理；如已污染，提示用户手动重置 |
| 被测地址不可达 / 应用未启动 | 不进入执行，先排查环境（§0.3），提示用户 |
| 执行超时（单模块 > 30 分钟） | 中断，提示用户精简范围 |
