# 回归测试使用统计 · 产品思考

> 技术实现见 [docs/handover/regression-stats.md](../handover/regression-stats.md)
>
> 姊妹模块（功能测试统计的产品思考）：[insights/test-usage-stats.md](./test-usage-stats.md)

## 解决什么问题

「使用统计」原本只量功能测试（AI 生成/采纳/复核）。回归测试上线后，套件、轮次、脚本重放沉淀了大量使用数据却无处呈现——用户看不到「回归到底在被怎么用、跑得怎么样」。本次把回归使用数据也纳入统计模块。

用户最初给的三个种子诉求：**套件新增、套件执行、用例执行记录**。

## 为什么是这三图 + 一表（而不是种子的字面翻译）

裸计数是虚荣指标。对标 TestRail / Xray / Zephyr / qTest / Datadog CI Visibility 的回归分析后，把种子升级为「趋势与结构」：

- **套件执行趋势**（按 `mode` 拆全量/仅失败）← 「套件执行」种子。看的是节奏与重跑占比，不是一个裸数字。
- **用例执行趋势** ← 「用例执行记录」种子。放在执行量维度看投入趋势。
- **脚本重放 vs AI 执行** ← 本产品差异化。呼应「脚本重放优先」架构：重放通过率下滑 = 沉淀脚本在腐烂，是别的测管产品没有的信号。
- **套件明细表** ← 「套件」维度的现状盘点：覆盖率、执行次数、最近通过率、平均耗时、重放占比一行看全。

## 关键设计决策

### 1. 文件态聚合，不复用事件表
功能测试统计是跨项目事件溯源；回归数据是单项目文件态、且带 `via`/`circuitBroken`/`quarantined`/`verdicts.cls` 等事件层不携带的富字段。硬塞进事件表 = 把整个回归数据模型二次序列化。回归的发版口径本就是单项目问题，混进「全部·本机」跨项目 global 会误导。故独立聚合、锁定当前项目。（详见交接文档「为什么不走事件表」。）

### 2. 二级切换而非合并大盘
功能测试是跨项目「本机」、指标是采纳率/准确度；回归是单项目、指标是通过率/重放。放同一屏 KPI 会出现两种分母语义并存，用户无法解读。故 `功能测试 / 回归测试` 切换，两套各自渲染，复用同一批 SVG 图元与卡片外壳，改动最小。

### 3. 诚实口径优先于好看
- **熔断轮（circuitBroken）整轮排除**：认证中途断=结果不可信，不能让一次掉线污染通过率/重放占比，且在明细里显式标注而非静默丢弃。
- **进行中（running）轮不出结论**：counts 未定就不进趋势。
- **疑似 flaky 是候选而非事实**：回归各轮跑在变化的产品版本上，跨轮翻转 ≠ 真 flaky（本期未做 flaky KPI，正是因为它需要「同版本连跑」才能定性，避免给假结论）。

## 用户驱动的范围收敛（2026-07-14）

提案给了完整版（4 KPI + 6 图 + 明细下钻）。用户看完原型后**主动收敛**到：套件执行趋势、用例执行趋势、脚本重放 vs AI、套件明细四块，其余「先不用」。据此交付精简 v1。这是「先给方案+原型、确认后再开工」流程的价值——避免了过度建设。

其中「套件新增趋势」因 `RegressionSuite` 现仅有 `updatedAt`、无 `createdAt`，存量套件无法回溯历史，用户权衡后**决定不做**（而非为它新写字段向前累积）。

## 已知局限 / 未来方向

- **单项目口径**：无「跨项目回归总览」。未来若需要，可在 toggle 之上再加一层，或给 `execution_completed` 事件补 `roundId` 打通跨项目回归执行量。
- **扩展位已留**：聚合层其实已具备算出发版就绪度（`mergedStats`）、失败归因（`verdicts.cls`）、本轮变化 delta（`case-history` diff）、flaky 候选（`health`/`consecutiveRunFailures`）的数据路径——后续要加只是加渲染，不需重做数据层。
- **套件新增趋势**：若未来给 `RegressionSuite` 加 `createdAt`（向前累积），即可补上这个种子诉求。
- **重放占比读 run.json**：套件明细的重放占比需展开近 50 轮 run.json，轮次极多的老项目更早的轮不计入该列（已在脚注说明）。

## 参考

对标产品的回归分析呈现：TestRail（状态分布/里程碑通过率趋势）、Xray & Zephyr Scale（执行状态 gadget / 最新态发版就绪）、qTest Insights & PractiTest（执行进度/自动化占比）、BrowserStack Test Observability & Datadog CI Test Visibility（flaky 率/稳定性/时长趋势/新增-修复-持续失败）。本期取其「趋势而非裸计数」「诚实排除不可信数据」的共识，差异化落在「脚本重放 vs AI」这条本产品独有的主线。
