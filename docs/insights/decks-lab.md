# Decks Lab：长文档与企业模板（产品思考）

> 技术实现见 [docs/handover/decks-lab.md](../handover/decks-lab.md)

## 解决的用户问题

1. **长文档做不成好演示**：论文、报告直接丢给模型，会被截断、丢掉表格数字、图片也用不上。现在先按作者自己的章节切成语义块，规划时每张卡标明引用了哪一块、配哪张图，写作时以原文为依据。
2. **企业模板“只像颜色不像模板”**：用户上传公司或 Gamma 导出的 PPTX，期待的是模板的视觉语言，也就是图形组件、装饰图、Logo 和版式节奏，而不只是配色。所以我们读出模板里可复用的图形组件（四叶草、链条、时间轴、编号列、图标网格），让内容按项数去匹配这些组件，并且能按条目数规整伸缩。
3. **图片摆放随意**：原来按顺序把图塞进固定 40% 的版位。现在按文字量决定放几张、多大；按类型决定能否裁切（图表永不裁切）；同系列的图才并排；模板装饰图跟着模板节奏走。

## 为什么这样设计

- **通用规则，而非逐模板适配**：组件识别是 “重复单元 + 共享核心”，排布是 “重复步长周期”，图案组件用 “像素自相关周期 + 分段拼接”。同一套规则在 9 份风格迥异的模板上验证过，新模板不需要写代码。
- **项数一变，图形要跟着变**：用户明确要求条目加减时，图形组件也同步增减、间距相等、排版规整。所以伸缩的单位是整个单元，包括它的配图、编号、卡片底框；而链条这类整图组件则按图案周期补环或减环。
- **不截断、不硬塞**：组件放不下当前项数时退回主题网格，绝不丢条目；匹配阶段会主动避开放不下的组件。
- **可解释**：测试台展示每张卡的引用、匹配到的组件和得分理由、每条媒体决策，方便产品和设计判断规则是否合理。

## 已知局限与方向

- 真实模型（如 qwen）尚未端到端验收，所有截图都基于离线演示模型。
- 不规则构图的组件只能按原项数使用。
- 组件目录尚未跨模板沉淀；章节分隔页还没有生成。
- 下一步：用真实模型跑长文档 + 多模板的对照评测，然后沉淀组件目录（按类型、容量、适用内容）。
