# 批量会话导入：为什么这样设计

> 技术实现见 [docs/handover/batch-session-import.md](../handover/batch-session-import.md)

## 解决什么用户问题

CodePilot 支持把 Claude Code CLI 的历史会话导入成 CodePilot 会话。配合 cross-host session import（扫描 bsApp 影子 HOME），一个用户在多台机器/多个 Agent 间产生的会话可能多达上百条（实测列表 184 条）。

原来的对话框每行一个"导入"按钮，点了就立刻导入并跳转——**一次只能搬一条**。对"刚换机器、想把上一台的一批会话都搬过来"的用户，逐条点击 + 每次跳转打断，是明显的体力活。本次加多选/全选/批量导入，把"搬一批"变成一次操作。

## 关键设计决策与取舍

### 1. 多选是"叠加"而非"替代"——保留单条按钮
最初考虑过改成纯多选模式（去掉单行按钮，统一勾选 + 批量）。最终保留单条"导入"按钮并存：
- 单条按钮自带"导入即跳转到那个会话"的高频快捷路径，是"我就想看这一条"的最短操作。
- 多选是给"搬一批"场景的新增能力，不该牺牲老路径。
- 代价：单条按钮要 `stopPropagation` 避免点它时误勾选整行——小成本换两种心智并存。

### 2. 全选 = 当前过滤结果，不是全部
"全选"只选当前搜索过滤后可见的行，而非库里全部会话。理由是**最小意外原则**：用户搜索后看到的就是他关心的子集，"全选"应符合"所见即所选"。若偷偷把不可见的也选上，会一次性创建一堆用户没看到的会话副本，是危险的。

### 3. 选中跨搜索保留 + 隐藏提示
选中集合不随搜索清空，支持"搜 A 选几条、再搜 B 选几条"的累积式多选。但这会带来"幽灵选中"困惑——明明列表只剩 63 条，却说"已选 183"。所以加一行小字提示"另有 N 个不在当前筛选内的已选会话"，让隐藏的选中可见、可预期。这是"功能灵活性"和"状态透明"之间的平衡。

### 4. 后端用批量 endpoint，不是前端循环
看似前端 `for` 循环复用现成单条 API 最省事（零后端改动），但调研发现两个性能陷阱：`parseClaudeSession` 每次都遍历全部 project 目录做 fs 探测，单条 route 每次又 `getAllSessions()` 全表查重。N 条走 N 次 = N 次全目录走查 + N 次全表查重。新增批量 endpoint 把查重降到一次、错误聚合集中在服务端，是"多写一个文件 + 抽一个 helper"换"更快 + 前端更简 + 错误边界清晰"。这是规划阶段 Plan agent 翻出 parser 实现细节后才敢拍的板——否则很容易顺手选了前端循环。

### 5. 批量完成不跳转
单条导入会跳转到新会话，符合"导入就是为了打开它"。但批量导入了 N 个，跳哪一个都不对。所以批量改成：聚合 toast 汇报"成功 X / 已存在 Y / 失败 Z" + 刷新侧栏列表 + 弹窗不关（让用户看结果、可继续搬）。已导入的行就地标记"已导入"并锁定，防重复点。

### 6. 部分失败不中断、永远 200
一批里有坏会话（解析失败/无消息）很正常。批量 route 每条独立 try/catch，单条失败只记 `failed` 不影响其余，整个请求仍返回 200 + summary。把"部分失败"表达成数据而非 HTTP 错误，前端才能优雅地说"5 条里成功 4 条"。

## 已知局限与未来方向

- **真实批量导入未在真实数据端到端验证**：为不污染用户真实 DB，验证只覆盖了 UI 交互全链路 + endpoint 契约（fake id 无副作用）。`importOneSession` 是从原单条逻辑等价抽取的，行为不变，但建议产品侧手动验收一次真导入。
- **无逐条真实进度**：批量是单请求，只能显示"忙碌中"+ loading-toast 原地更新，给不出"3/10"。会话量很大时用户感知不到进度。未来若要真实进度，可改 SSE 流式逐条推送，或前端分批。
- **可能的演进**：导入前预览会话内容、按 project 分组批量导入、导入后批量打标签/归类。当"搬一批"成为常用动作后，这些组织能力会变得有价值。

## 背景串联

本功能是 cross-host session import（[handover/cross-host-session-import.md](../handover/cross-host-session-import.md)）的自然延伸：前者解决"看得到别处机器的会话"，本功能解决"高效地把它们搬过来"。两者合起来构成完整的"跨机器会话迁移"体验。
