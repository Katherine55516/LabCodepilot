# Decks：为什么按 Gamma 的方式重做一套演示模块

> 技术实现见 [docs/handover/decks.md](../handover/decks.md) · 依据：[Gamma 逆向报告集](../research/gamma-reverse/README.md)

## 用户问题

- 现有 `/ppt` 模块追求“来源忠实 + 模板保真”，门禁多、停顿多（要点陈述了来源没有的数字就停下等作者）。它在严谨场景里有价值，但大量用户要的是 Gamma 式体验：几分钟内从一句话或一段笔记得到一份好看、可改、可演示的稿子。
- 用户明确要求：完整逆向 Gamma，在另一个分支复刻它的架构、功能、工作流以及对 media、content 的处理，包括前端界面，作为下一版本的备用。

## 为什么是“并行新模块”，而不是改 `/ppt`

1. **风险隔离**：`/ppt` 有大量已验收的规则和回归，在它上面改流程会动到已经稳定的东西。Decks 独立目录、独立表、独立路由，不碰 `/ppt` 的任何代码。
2. **两种产品哲学并存**：`/ppt` 侧重严谨，适合研究、报告类；Decks 侧重速度和观感，适合推介、教学、内部分享。下一版本可以按场景选择，或者合并两者的长处。
3. **本机运行**：Decks 在本机 Next 服务里调用用户已配置的服务商，不依赖远程沙箱和桌面 worker，本地 dev 就能完整验证。Gamma 的模型也在服务端运行，这里对应的是本机服务端。

## 关键设计取舍

- **大纲即内容**：Gamma 实测中，大纲卡片已经是压缩好的最终要点，后面的生成只负责排版（报告 03 §3）。所以作者在审阅大纲时就能决定讲什么。我们照此设计：大纲卡片带完整要点，可合并、增删、排序，并能逐卡写指令。
- **卡片数是软目标**：Gamma 的页数跟着内容走（报告 02、03），我们也不强制精确页数。
- **按内容选组件**：数字用指标卡，流程用步骤，日期用时间线，表格数据用原生表格或图表。这是 Gamma 高密度但不拥挤的来源（报告 03 §4）。组件都是原生块，导出到 PPTX 仍可编辑；Gamma 的图表不可控、结果随机，我们的原生图表数据确定，这一点比 Gamma 强。
- **装饰图**：报告 09 认定，没有装饰图是我们和 Gamma 之间最大的媒体差距。Gamma 会自动决定每张卡要不要图、放哪里、放什么。我们让写卡模型按内容选位置（左 / 右 / 上 / 背景 / 无）。图片来源可以是 AI 生成，也可以是原创的主题 SVG。后者离线可用、不涉及授权、同一张卡永远同一张图。
- **输入图片链接按 Gamma 的宽松语义处理**：抓得到就托管并优先使用，抓不到就跳过，不会因为一张失效的图挡住整份稿件（与 `/ppt` 的“必需来源”语义相反，详见技术债务 #34）。
- **编辑先定范围**：Gamma 5 的 AI 编辑先让用户选范围（整份 / 卡片 / 元素），再给出前后对比，整组接受或恢复（报告 06）。我们照做，并且每次应用都留版本，可以随时恢复。
- **生成中的指令排队**：Gamma 不在生成时打断当前卡片，而是排队、生成完再执行（报告 02、06）。这样比实时打断更稳定，我们照做。
- **mock 模型要显式标注**：没有服务商时用离线演示模型，界面明确提示“演示模型”，不冒充真实生成。

## 不复刻的部分与理由

- **Gamma 的名称、Logo、视觉风格**：属于对方的商标与视觉识别，不复刻，我们用自己的设计体系和原创主题。
- **图库 / 网页图片来源**：需要授权的第三方 API，暂不做。
- **站点发布、分析统计、多人协作**：对桌面应用价值低，或需要云端基础设施。
- **Gamma 的内部 schema**：不可观测（报告 01 🔴），我们用自定义块模型，正好可以直接映射到 PPTX 原生对象。

## 已知局限

- **容量判断**：按行估算，不是真实排版测量。少数卡片在屏幕上仍可能偏满，PPTX 导出时会按比例缩小字号。
- **内容质量**：取决于用户配置的模型；mock 模型只用于演示和测试。
- **文件导入**：还不支持 PPTX/PDF 导入，也还没接入 Gamma 兼容 API 和 MCP。

## 未来方向

1. Gamma 兼容 API 可选指向 Decks 引擎（Gamma 5 agent 端点的语义与 Decks 的工作流天然吻合）。
2. 用 MCP 暴露 `generate` / `read_deck` / `edit_deck`，让 Claude、ChatGPT 直接调用。
3. 把 `/ppt` 的事实核对作为 Decks 的可选“严谨模式”，合并两边的长处。
4. 文件导入：PPTX 按页解析为卡片，PDF 作为来源。
