# 对话流交错渲染 — 产品思考

> 技术实现见 [docs/handover/conversation-interleaved-flow.md](../handover/conversation-interleaved-flow.md)

## 解决什么用户问题

旧设计把一条 assistant 回复拆成两块：**工具调用 + 思考折叠在顶部**（"N completed"），**文字输出全部堆在下方**。

用户反馈：工具调用一多（比如连续 Read/Edit 一串文件），就看不出 AI 的真实工作过程——「先说了什么 → 调了什么工具 → 看到结果后又说了什么」这条因果链被打散了。折叠的 "N completed" 还要点开才看得到调了啥，不直观。

## 为什么这样设计

**参考 Claude 桌面版**：它把文字、工具调用、思考按发生顺序自然地从上往下排，读起来就是 AI 思考和行动的真实时间线。用户明确指向这个体验。

**关键决策（和用户确认）：**

1. **全程交错，不只是完成后**。用户的痛点恰恰在「正在调一堆工具」的流式阶段——如果只在 turn 结束后才交错、流式时还是旧的折叠样式，等于没解决核心痛点。所以实时流式就边出文字边出工具行。

2. **工具平铺单行，不折叠、不归组**。用户原话「也不需要把 tools 这样折叠起来，调用了什么就写出来什么按顺序排列就行」。所以去掉 "N completed" 折叠头，连续的 Read 也不自动归成一组——每个工具一行，所见即所调。

## 为什么能做到（技术可行性的洞察）

调研发现一个关键事实：**顺序信息其实一直都在，只是被前端丢掉了**。SDK 返回的 content blocks 本来就是有序的，SSE 事件到达顺序也正确。旧代码把事件拆进了三个独立 buffer（文字 buffer / 思考 buffer / 工具数组），最后还硬编码成「思考→文字→工具」重新拼接——顺序在累积和重建两步被人为抹掉了。

所以这不是「拿不到顺序」的难题，而是「把已有的顺序保留下来」的工程。改动集中在累积逻辑和渲染层，不需要动 SSE 协议或后端。

## 工具结果的可见性：让每个工具都能展开

交错改造后工具按时间平铺成单行，但有个遗留缺口：**只有「思考」能 hover 点开看内容，其它工具（Read/Edit/Bash/MCP…）只显示一行摘要 + 状态点，看不到工具到底返回了什么**。用户反馈：除了思考过程，其他工具调用都没有输出返回结果。

设计上不发明新样式，直接把「思考行」那套已被验证的交互——hover 出 `>`、点击展开——推广到每一个工具行。心智一致：所有可展开的行长得一样、点法一样。

几个取舍：

- **运行中默认展开，跑完折叠**。正在跑的工具（尤其 bash）默认展开，实时输出一眼可见；完成和历史默认折叠，列表保持干净。
- **bash/agent 完成后回落到通用「参数+结果」面板**。它们原本只在运行时显示流式进度，跑完反而看不到最终结果——agent 的最终产出、bash 的完整输出，这才真正看得到。
- **忠实展示 + 安全封顶**。结果按 200 行 / 8000 字符截断并提示剩余，既看得到大概，又不会让一个几千行的 Read 把对话撑爆。
- **参数也展开**。光看结果常不知道「改了什么」（如 Edit）。展开区上半部分显示调用参数，对 Edit、MCP、未注册工具尤其有用。

本质上和交错改造同源：**数据一直都在**（SDK 的 tool_result 早就按 id 配对存好了），缺的只是把它展示出来。

## 旧消息的顺序：在导入时重建

最初以为旧消息顺序"永久丢失"，其实只是丢在 CodePilot 自己的 SQLite 缓存里——Claude Code 的 JSONL 转录把每段 thinking/text/tool 都带时间戳独立存着，顺序完好。

因为应用还没发布，没有线上老用户的旧消息，唯一会碰到旧 JSONL 的入口是**导入会话**。所以把交错重建放进导入流程：导入时把一个回合的多行 JSONL 合并成一条有序消息，顺带修了旧导入逻辑丢 thinking、丢 tool_result 的 bug。导入进来的历史会话现在和新对话一样是完整交错的。
- 取消折叠后，超长工具序列（几十个 Read）会让消息变长。当前选择「忠实展示」优先于「紧凑」。若后续反馈太长，可考虑对连续只读工具做可选归组（技术上 `ContextGroup` 还在）。

## 未来方向

- 工具行展开区目前是纯文本 / JSON；可针对特定工具做富渲染（Edit 的 diff 高亮、图片结果就地缩略、TodoWrite 的清单视图）。
- 展开区的截断阈值（200 行 / 8000 字符）目前写死；超长结果可做「展开全部」或外部查看器。
- 给思考块更克制的视觉权重，避免长思考淹没正文。
