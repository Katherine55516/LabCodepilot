# PPT 质量等级与可解释工作流

> 技术实现见 [docs/handover/ppt-experience-quality-routing.md](../handover/ppt-experience-quality-routing.md)
> 状态：设计已进入实现，验收仍在进行。

用户需要能完成演示文稿，不需要先学会供应商的模型命名。三个质量档位表达投入，内容合同继续表达保留什么。快速模式也必须保留必要事实、图片、语言和人工修改；严谨模式也不能制造额外事实。

Gamma 的逐卡反馈适合降低等待的不确定性，本项目增加固定页面和可编辑 PowerPoint 的要求。因此，流式草稿与可发布内容必须分开：当前页立即可读，已提交对象可编辑，发布仍依赖实际来源、排版与导出检查。暂停和刷新应保留眼前工作，而不是退回全套模板。

质量路由的可信度来自可验证能力和执行轨迹。配置中只有一个模型时，可以用不同角色独立调用，但必须说清是同模型兼任；没有评测的模型不能因名字听起来更强就标为推荐。没有价格就报告未知费用，失败请求也占用预算。对于未知交付结果，先暂停让用户检查已有草稿，避免无声重放。

原生模板同时携带设计和旧内容。默认清理旧报告，明确选择固定对象，在副本上做整体重构，能兼顾品牌延续与事实隔离。背景图中的文字需要真实视觉检查，不能仅凭一个 `design_only` 字段宣布绝无污染。

真实短稿复核暴露出另一点：完整保留来源不应变成每个短标题都独占一页。现在在确认前以完整来源归属和真实容量为约束合并稀疏邻页，既不填造事实，也不靠把内容藏进备注充实页面。固定页数、已经确认的计划和人工锁定继续由用户控制。结束页本身保持简洁，不用巨大的空内容卡假装信息充实。

工作区保留顶部批量栏，强调选中范围和部分失败；创建流程保留大纲确认，强调按钮可达与输入可恢复；聊天采用固定输入和单一历史滚动。它们遵循同一目标：用户始终知道当前对象、当前动作和下一步。

参考与依据见[执行计划](../exec-plans/active/ppt-experience-quality-routing-20261014.md)中的 Gamma 官方资料、项目实测记录和原型对照。后续应依据同源基准调整等级：只有严谨确实改善质量、均衡确实取得有意义的投入平衡时，才能宣传效果；当前不承诺固定速度或成本降幅。


## 验收中新暴露的边界

来源正文由程序原样绑定时，模型不应再生成第二份正文；提示和 SDK schema 必须表达同一个任务。章节序号与业务数字需要不同的可核实语义，不能直接放宽所有数字，也不能拿来源章节数字授权新的百分比。长输入的处理规模与推理难度应分开：规则清楚的段落集合可用强规划模型而关闭额外隐藏推理，代码/公式/大表再按硬信号增加投入。

PDF 字形、原生模板和暂停编辑都必须检查实际产物。测试环境缺少生产镜像字体时，先补齐隔离依赖并记录身份；更改内容或缩小字形不构成修复。最新进展和未通过案例见执行计划 §11.3。


真实旧模板验收再次说明需要保留严格门禁：模板内部重复对象 ID 会使“删除一个旧对象”实际影响两个对象，应建立可审计工作身份而非降低对象数量检查。跨章节合并同时要更新导航标签；多数章节标签不能代表整页所有来源。封面/致谢应满足其叙事功能，不为了填满旧正文槽位重复事实。来源位置、文件格式等技术标签也不属于用户需要的幻灯片图注。这些调整来自实际导出/审查失败，验收尚未全部完成，详见执行计划 §11.4。


实际模板通过语义审查仍可能卡在发布：模板设计复用不应继承“保留每张旧报告页”的限制。隔离渲染候选也属于用户可恢复性的必要条件，失败不能令状态停留在生成中。逐页视觉核验又发现文字框与胶囊分离测量、旧数据表横线未一起退役，两者均需要按视觉组处理。对原始长稿的代码/流程不可容纳问题，继续保留正例失败，不通过改输入、转备注或降固定字号掩盖；拟以严格来源行范围分页补齐，当前尚未全部验收。


长稿实测进一步说明：冻结计划前必须校验真实写作协议和最终页面空间，而不只是估算字数。一个两行标题即便能显示，也可能超出写作预算；一个代码块即便在页面内，也可能覆盖页码。布局修复不应把错误留到冻结后的写作者反复尝试。

目录的来源 ID 全覆盖也不足以证明观众看到的主题完整。按词截短标签曾删掉整个媒体主题，独立审查拦截是有效发现。现在让模型在固定容量内重新命名全部主题，保留审查的拒绝权，不把元数据压缩当作语义压缩。

### 真实评审也需要保留显示语义

原生上标不能只传展平字符给文本审查；数学显示、精确引用投影和来源必须分别保留。章节眉题、目录标签、编译页码与正文事实也要保留不同角色，否则强模型可能把简短主题当穷举，把来源内编写说明当新用户命令。角色信息帮助判断，但不构成自动通过；模型发现和失败必须保留。

同样，零媒体模板的守恒指标没有分母，应记“不适用”；稀疏页能否合并要测合并后的布局，不能相加旧页高度。真实长稿还要求完整的引导句与清单关系：同页能容纳则合并，不能容纳则提前保留清晰的跨页提示空间。


### 改进必须落在实际失败所在的层

长稿的几十个有效局部分片不能因为总和超过页数上限而全部作废。保留预算内的有效工作、以相同字号测量可合并的页，再明确保留真正的容量冲突，才符合可恢复流程。合并资格阈值不会代替来源/空间检查。

标题语言检查也不能只看已经被显示规则剪短的字符串：语言看似正确，章节主题和代码行范围却已经丢失。需要对完整规划元信息进行修正，并把译后的范围与实际来源绑定。目录模型在重复提示后仍可能违反字符容量，确定性 schema 应直接表达已知边界，语义完整性仍由独立审查保留拒绝权。

98 项回归全绿后真实 Gamma 仍暴露目录失败，说明冻结构建、原输入复验和逐页成品检查是不同证据。修复这些问题时不能擦掉此前失败，也不能把一次安全拦截当作可交付的正向成品。


实际 15 步流程的贪心容量分页会留下 12＋3 的稀薄尾页。对无函数边界的有序 ProcessBlock，可在不改变源行、字号和页数的前提下重新选择相邻分片边界，但左右范围都必须重新通过实际容量合同；CodeBlock 不适用这种再平衡。扩大 critic 修复预算不能代替修复确认前分页。

QA 服务重启期间，旧 service-ready 文件不代表新进程已经就绪。真实基准创建前必须核对 ready 与 loaded-code 的 hash 和时间；发现错误时保留原记录并排除，单独观察存留项目，不能重写身份后将旧记录当作合格样本。


标题检查要验证排除 locator 后的真实主题：`(rows 1–8)` 虽含英文和正确范围，也不是主题。用户锁定的封面应在规划元数据校验前成为候选标题的权威，不能检查已被实际预览忽略的模型封面。标题的自动去重与缩短必须共享同一预算，否则“缩成相同主题→自动加长限定语→再次溢出”会消耗全部修复预算；提供其他页主题并在局部 delta 阶段拒绝重引入重复，比放宽标题门禁更有用。


真实约束解码不能只靠标准 regex substring 语义推断。suffix-only `\(lines A–B\)$` 在当前服务商实际只产出 locator；同服务商对照证明完整 `^.+\s+...$` 才允许主题和 locator 一起生成。局部结构 schema 应描述完整目标，验证保留完整语义和范围，不能靠无限提示重试。

数学评审的观众文本应来自 typed runs；字面展平投影只用于服务器精确 quoteId/证据绑定。将 `106`、`displayText=10^6` 同时当作可见文本会诱发错误冲突。显示视图修复同时增强来源数学结构检查，确保真实丢指数仍失败。CJK inline OMML 在实际多行列表中有 1.38pt 的边界差，需在共享分页测量中预留可验证余量；不能关闭实际导出可见性门禁。
