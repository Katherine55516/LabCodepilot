# PPT Round 7 的产品取舍

对应：[技术交接](../handover/ppt-gamma-parity-round7.md)。

用户看到的是正在生成的演示文稿；预先展示所有空模板会让人误以为内容已经落页。当前页必须承载真实生成文字，完成页可阅读，未来页只列计划。草稿可以临时增高，正式页面必须通过真实尺寸校验；不以裁掉下半段换取固定比例。

主题语言和证据语言是两个决定。封面、页标题、目录和结束语统一采用输入的主要语言，正文可按用户选择保留双语。不能因某页出现两种语言就强加平行标题，也不能因标题单语而丢掉另一种语言的独立事实。

大纲模型应做内容选择，而代码应解决来源 ID、去向、唯一归属、元数据长度等机械约束。可恢复错误列出修正后交用户确认；来源真实性、语义蕴含、媒体守恒和最终版面仍需校验。目录标签压缩后同样要独立审查，不能为了首轮接受率放行错误主题。

图片导入不等于只统计候选数量。验收走到原生 PPTX 并核对图片哈希；缺少替代文字时保留相邻段落和实际位置，不猜图中的事实。数值图表只有明确来源时才生成可编辑图表，模糊描述保留为文本。

这轮真实测试还说明：功能正确的语言检测若放在容量循环里反复执行，会使整个应用几分钟不响应。缓存必须跟随实际输入内容失效，不能沿用项目 ID 得出过期语言。性能问题也会表现为“按钮没用”或“模型超时”，需要看真实接口与 CPU 证据。

后续采样还发现，复制模板图片和多页签反复读取整个项目也会阻塞真实任务。媒体字节不可变，可以共享；文本、样式和位置必须独立复制。列表/可启动检查只缓存轻量投影，实际编辑依然重新读取完整项目，缓存必须能发现其他进程的原子保存。并发预算也应属于账号，而不能随着用户打开的浏览器数量翻倍。

真实测试还暴露了两种信任问题：暂时读取失败不应让用户失去已完成的大纲、更不应重复创建项目；模型擅改已确认标题也不需要反复调用模型，代码应保留用户确认值并列明纠正。审查同样必须尊重用户已确认的概览/备注合同：有一页摘要，并不意味着所有可选备注都要重回正文。校验台账和来源身份后解消可选备注，明确条件和用户必含要求仍是独立义务。来源中明确的算术矛盾则必须让用户核对，不能为了让三份样本通过而悄悄改原文。

当前边界：本轮使用独立本机 API/前端、加密 BYOK 配置和主机文件 IO 适配器。它验证真实模型与生产 PPT 逻辑，但不代表远端 Docker 部署、其他托管模型或云端发布已经验收。三份真实稿的最终结果尚未完成，不能用专项测试通过替代。
