# PPT Workspace M4 交接

## 数据和编辑边界

`deck.slides[]` 继续是可编辑事实源。M4 给每页增加 `blocks[]`（最多 2 个）与 `layout`（`text-first` / `visual-first`）。块类型仅有 `image`、`chart`、`table`、`shape`；图表数值、标签和表格单元格均来自用户编辑，不由模型创建。图片在浏览器缩放后以 JPEG 数据 URL 写入 IR，单图上限 512 KB；这使当前按账号存储的项目 JSON 可跨设备读取，但大量图片仍会增加项目体积。服务端 `ppt-blocks.mjs` 严格验证块类型、格式、尺寸、数值和 ID，视觉页限制最多 3 条短要点。旧版仅有标题/要点的项目仍可打开和保存。

Paste 新建模式同时接受文字和图片：`textarea` 的原生文字粘贴保持不变，同时读取剪贴板中的 PNG/JPEG，也提供多选文件入口；最多 4 张。图片先保存在 `source.images`，修改粘贴文字并重新生成大纲时不丢失。确认大纲后，生成编排器跳过封面，按每页最多 2 张把图片加入 `deck.slides[].blocks` 并设置 `visual-first`，必要时确定性收缩该页模型要点。模型不读取图像、不决定页面几何；因此当前能力是保留并排版用户图片，不包含 OCR、视觉理解或自动图片描述。

`PATCH /ppt/projects/:id` 支持完整 `slides`，也支持 `slidePatches[]` + 可选 `appendSlide`；包含图片的客户端编辑走局部上传，减少请求体重复传输。两种保存都检查 revision，并在 Cowork 内重新渲染 PPTX 后原子保存项目。`template` PATCH 只重排重渲染，不调用模型。`POST /ppt/projects/:id/rewrite` 只把选中页标题、要点、来源和用户指令交给无工具模型；指定 `blockId` 时仅改写图片说明或形状标签，不允许模型更改图表数值和表格。验证模型回复后重渲染，修订号递增。UI 的撤销/重做是本地历史，撤销 AI 结果后需要再保存。

项目列表只返回封面标题等摘要，不返回完整视觉块、节点或上一版内容快照；打开单个项目时再获取完整 IR。这与局部页补丁共同控制大图项目的日常传输量。

## 渲染与 UI

PPTX 渲染器使用 `python-pptx` 的图片、原生图表、表格、基础形状；中文导出统一使用 `Arial Unicode MS`，避免此前引用 Cowork 内部 Noto 字体后在本机 Office/LibreOffice 缺字。导出阶段还会把 `python-pptx` 可能写出的负数图表轴 ID 规范为 OOXML unsigned ID，保证严格读取器可打开。PDF 渲染器使用相同的验证后 IR 和确定性 Matplotlib 绘制。页面顺序和坐标由代码按两种布局计算，LLM 不提供几何。编辑/演示预览读取同一块数据；编辑器增加图片上传、图表标签与数值、表格文本、形状及颜色、布局切换、页面搜索、撤销/重做和选中页 AI 改写。两种导出仍通过项目 Cowork 容器完成。

## 验证与剩余边界

- `selftest-ppt-m4.mjs` 覆盖块输入验证、局部改写、修订冲突、主题切换、局部保存、跨账号隔离，并用真实 `python-pptx` 重新打开含图片/原生图表/表格的产物。
- PPT 定向 Playwright 覆盖 M4 的块编辑、撤销/重做、模板切换、局部 AI；桌面与 390px 截图检查预览布局。
- 本机用临时安装的 Matplotlib 跑通含四类视觉元素的 PDF 脚本并用 `pypdf` 重新打开核对 3 页；同时修复缺少 Noto 字体时的回退字体。测试依赖只放在 `/tmp`，未加入应用依赖。本机没有 Docker；真实 Cowork 容器、跨设备和安装包仍须部署环境验收。丰富图片项目的数据容量、渲染耗时和跨设备下载时间也应在真实环境测量。
