## 2. 已确定的产品约束

1. 保留“手动读取并估算 → 调整页数/详细度 → 生成大纲 → 确认 → 页面生成 → 验收 → 导出”。
2. reader 完整读取后的 LLM 建议是唯一推荐页数；用户确认的 N 是下游总预算。代码仅给出实际容量诊断，不再另造一个推荐页数，也不默默拆页。
3. 不把未上页细节转入备注，不增加“详情见备注”。存储中保留来源与取舍记录，不等于向演讲者备注复制全文。
4. 用户在大纲阶段决定摘要和表格取舍；生成/排版不能临时删必要事实、条件、比较对象或表格数据。汇总“其他”必须有可加总的真实口径及明确选择。
5. 容量修复顺序：调整合法版式/组件 → 删除表达冗余而保留含义 → 在既有可读下限内小幅调整字号 → 预算内重新分配已选内容。仍失败则说明具体阻碍，请用户修改展示范围或 N。
6. 简洁/标准/详细决定解释深度，不用固定字数比例注水；所有执行策略使用相同硬门禁。
7. 目录、章节和结束页按内容与模板选择，不机械占页；结尾应承载来源支持的结论。
8. 草稿允许预览、定位与局部修复，硬门禁未过不能正式导出。测试保持模型 simulate，直到用户要求恢复真实本地模型；本次 Gamma 网页观察是单独的竞品实测。
9. 不重启或修改 3141/3143，不把当前研究任务变成服务部署。

## 4. 全局叙事和页数：具体设计

### 4.1 先读语义，再估算；确认预算后展开页面

推荐链路：

`实际解析 → 全输入阅读/有覆盖证明的分层阅读 → Brief 与语义义务 → 主题/关系初步归并 → LLM 推荐页数及依据 → 用户确认 N → 全局页面蓝图 → 并行页面规划 → 大纲验收 → 确认大纲 → 写作与组件生成`。

“先估算还是先 outline”应区分：推荐前必须有主题与深度的粗规划，但不先生成一套固定页数的完整大纲再强迫用户接受。确认 N 后才生成完整逐页大纲。页数变化只重新分配与重审受影响的计划，不重复解释整个输入。

长输入的分层阅读需要 `readManifest`：段/结构范围、已读 ID、摘要版本、未解决冲突、全局整合完成状态。只读目录、头尾或固定字符前缀不能进入 `read_complete`。并行阅读可以降低耗时，但不能把局部重复估计相加当总页数。

reader 建议应包括 `recommendedPages`、可选范围与取舍说明、预算中封面/总结等角色占比、内容深度、双语处理方式、大型不可拆结构。与已有 schema 合并设计，不新增第二个页数权威。reader 使用模板实际容量概要作为上下文，避免推荐与模板完全脱节；容量层仍只检验用户确认的 N。

### 4.2 蓝图必须是论证结构

优先复用 `ppt-semantic-groups.mjs`、`ppt-semantic-editorial.mjs`、`ppt-global-outline-plan.mjs`、`ppt-page-contract.mjs` 的现有模型，不另建平行 IR。

每组已有 `readerQuestion/coreMessage/narrativeRole/supportRoles` 等字段；下一步先验证它们是否在 reader、逐页 writer 和 critic 全链路真实消费。不能只添加 schema 字段，却继续按 source 顺序分片。

逐页蓝图要求：

- 一个明确读者问题及来源支持的结论；主题标签不能代替结论。
- 来源与已选 claim/条件/数值/关系，说明定义、机制、对照、例子各自承担什么作用。
- 前置概念与下一页衔接；“解释先后”不自动成为“事实因果”。
- `introduce/explain/compare/demonstrate/decide` 等表达意图映射到既有角色，不轻率扩大生产枚举。
- 首次讲解与允许复用的上下文分开；相同术语出现不等于核心消息重复。
- 每个主体义务有主页面；一条全局结论允许在开场与收尾有不同作用，不让去重误杀合理复述。

代码职责：检查预算、ID、义务覆盖与依赖顺序，给出重复/碎片诊断。prompt 职责：决定归并、取舍、结论与解释链。不能用机械规则替代编辑判断。

### 4.3 Prompt 修改原则

reader：`先建立目标/受众/内容主张与语义关系，再提出一个主推荐页数。双语等义内容只计一个语义单元，保留两种语言实际显示所需容量；不要把15个章节机械映射15页。不要生成逐页正文。`

global planner：`在已确认N内先列完整页面蓝图；相邻短定义、机制、例子可以共同回答一个问题；不同子系统可并列而不捏造因果。先总览再细节，最后给实际结论。其他页面的核心消息是只读上下文。`

writer：`回答本页问题，保留范围内的关键事实、条件、否定和不确定性；用摘要重组说明，不逐段搬运。不得新增论据或以备注承接未呈现的必要内容。不得临时删改已确认数据。`

critic：`分别评估来源忠实、论点成立、页面独立价值、前后逻辑及媒体关系。给稳定目标ID、具体失败证据、最小修复范围；不得仅因页数较少就认可，也不得因不同措辞就判定新观点。`

## 5. 语义切割、摘要与双语

### 5.1 切割规则

先按完整解释链切割，再按容量安放。短定义与其机制、例子、限制可以同页；同一个分支图的判断/分支/汇合不应随表行切成两页。大型表与完整代码在明确选择保留时可以跨页，但要有同一逻辑主题、真实范围、连续标识和上下文。

每组给出可审查的 `mergeReason/splitReason`。若相关内容无法在一页可读展示，可以拆为“总览 → 深入例子”，而不是“行1–4 → 行5–8”作为默认叙事。不得因为追求变化而把完整跨页对照表强行改成无关图形。

### 5.2 摘要义务

复用 selection/obligation/claim 体系，将“全文字面保留”与“关键含义保留”明确分开：

- 定义、适用条件、否定分支、数值口径、比较对象、推断程度是语义义务。
- 示例可以按确认的大纲取舍；需要完整表、完整流程时按结构义务检查，不能借摘要名义丢数据。
- summary 不能只保留结论而抹掉前提；同一 source 的多个不同主张不能只用一个模糊句子冒充覆盖。
- 语义等价不能单靠字符串包含，也不能仅信模型自报。确定性事实/结构检查与独立模型审核并用，模型不可用则明确该层未验证。

### 5.3 双语处理

本输入有大量先英文后中文的等义段落。识别 `languagePair/semanticEquivalence` 后建立同一主张的两种语言投影，不创建两套独立主题。不能将所有英语术语、代码标识符计入标题主语言投票。

保留用户语言策略；若保持双语：以用户指定语言或当前段落主要叙述语言为主标题，另一语言在上方用较小字号与次级颜色呈现，仍满足模板可读性/对比度。代码、公式与专名不强制翻译。语言接近五五开时遵循全稿一致的已确认偏好，不逐页随机换主语言。

正文优先同组件成对组织，避免两个长段重复挤占页面。合并两种语言的“义务”不代表隐藏用户要求展示的任一语言，容量必须按真实显示文本测量。

## 6. 关系型媒体：逐项增强方案

现有 `ppt-semantic-media.mjs` 的 `semanticMediaForSlide()` 为兼容空入口；不能据此宣称全产品无媒体。实际来源绑定、source-media tasks 和布局路径已生成表格/流程/卡片，应先梳理真实调用链，再选明确入口增强，避免创建第二套互不相通的媒体系统。

|媒体|适用语义|生成前需提供|代码重点|硬验收/负例|
|---|---|---|---|---|
|层级树/分层架构|包含、分层、职责边界|节点、parent/contains边、层含义|原生节点/连线、深度宽度测量；禁止将有向依赖误作包含|父子完整、节点标签可见；漏子节点/层级倒置失败|
|决策流程|条件、Yes/No、fallback|decision、带条件边、终点与汇合|自动布线、边标签、分支去向；同页优先|否定分支/限制不能缺失；无来源新增判断失败|
|DAG|并行任务、依赖、join|前驱、fork/join、可并行集合|拓扑布局与跨行连接；循环需另选图类型|保留所有有向关系；并行变串行、箭头反向失败|
|泳道|角色/子系统与阶段协同|lane归属、阶段、跨lane消息|车道标签、跨lane连接及阅读顺序|每步角色正确；按装饰列排而无职责含义失败|
|对比矩阵|共同维度下的对象比较|对象、维度、单元值/条件|表格与对照卡自适应；保持共同维度对齐|不得把缺失值补成0，不改单位/比较范围|
|时间线/并行轨道|阶段、区间、关键路径|先后/起止、单位、示意或实测类型|相同时间轴，时长有来源才按比例|无数据不得编造耗时；示意图明确标识|
|机制图/带注释公式|公式组成、条件、结果|原式、符号、定义、来源关系|保留可编辑公式/文本、对应注释|不篡改数学符号、不能用装饰环图替代机制|

通用编译合同：source/claim/relation IDs → media intent → validated typed graph → 模板 style tokens → native scene nodes → 实际 render/PPTX → 可见节点/关系验证。复用现有关系和节点ID；对新关系种类必须定义版本、迁移与拒绝规则。

不能只以 `task=ready` 或形状数量证明成功。receipt 应证明必需关系映射到哪些实际可见节点/连线/标签，信息媒体、辅助图片、品牌、装饰分别记账。

失败只重试该媒体，保留 writer 文案、其他页、用户锁定节点和编辑命令。所有补丁校验 revision/run/source/epoch，旧响应不得覆盖新版本。若图无法适配，可使用来源忠实的对照/关系表作为明确降级草稿，但不能把它评为同等关系可视化质量。

## 7. 自适应排布与页面密度

布局先看表达意图与组件结构，再看模板真实角色/占位区/禁入区域/字体色板。优先复用 `ppt-source-layout-fit.mjs`、`ppt-layout.mjs`、`ppt-media-preserving-layout.mjs` 等实际路径；确定入口后补调用链测试。

- 同样是“少量文本”，核心结论页可大字号居中，机制解释页可增加有来源的关系图，独立价值不足的短定义页应建议合并；不能统一放大所有内容来填满空间。
- 全稿需要视觉节奏，但不规定每8页必须4种版式，也不为变化而破坏一致对照。
- 整体图作为一个可测量组件处理节点、标签和连接线；不能只让外框 fit，却把内部字缩到难读。
- 溢出报告带具体 slide/node/role/frame/font/measurement，区分标题、正文、表格、图例。实际 Office/PDF 验证继续保留。
- 低密度、连续表格、碎片页是诊断信号，结合页面角色和内容目标评审，不以面积百分比单独阻断。
- 区分Gamma 5固定画布、fluid设置与旧稿；不能笼统假定Gamma卡片均可无限增高（官方说明见第12节）。网页看着不溢出仍不证明实际PPTX可读；须对导出后的页数、尺寸、组件拆分再次核验。

## 8. 并行与渐进界面

先完成全局内容切割、主张去重、来源owner、页数与跨页依赖，再并行规划/生成独立页面。不能让每页独立理解全文后再拼接，否则容易重复介绍或丢失上下文。

建议状态是 `planned → writing → media_pending → fitting → checking → ready/failed`，先映射已有运行状态而非直接替换生产枚举。用户可见文字增量是输出草稿，不称模型思考过程。

画布只展示已经开始或完成的页面；待开始页在进度/导航中表示，不创建虚假的完整空白页面。完成顺序可以不同，最终顺序遵循蓝图；stream事件使用稳定slideId与revision，媒体稍晚补齐不让正文跳回旧版本。

## 9. 内容质量验收与 fixture

### 9.1 两类 fixture 分开

**结构保留 fixture**：继续验证全文解析、表/代码/关系、容量边界、原生导出与门禁，允许详细长稿。现有40页属于这一类。

**精炼编辑 fixture**：提供目标受众/深度与用户确认N，受控响应展示实际编辑蓝图、合理合并与摘要义务；至少两个可行预算，不以Gamma页数固定答案。包含“同组但非因果”“同术语不同结论”“开头/结尾合理复述”等负例。不能只给所有critic返回通过。

### 9.2 硬门禁与表达评审

硬门禁：N一致，必要事实/数据/分支与条件完整，来源及锁定内容守恒，无伪造关系/数据，字号达到实际政策下限，无裁字，发布与导出同源。

表达评审：整稿主旨、每页问题/结论、切割合理性、跨页重复、关系清晰度、媒体适合度、阅读顺序、双语层级、结尾决策。每条失败指向页面/claim/relation并给具体证据，不把“漂亮”“简洁”当可执行错误。

改动验收需覆盖：现有单位测试与相关自测；真实HTTP模型double全链路；编辑器实际按钮、流式过程、局部重试；实际PPTX重开及渲染。新增UI改动按AGENTS要求用CDP，不把直接API下载冒充原生下载。

## 12. 官方资料核查新增的关键发现（B类，非本次实机）

### B01：新旧创建流程不能混为一谈

当前Agent文档区分Plan、Express与配合Plan的Research。Plan先澄清、展示计划并等待确认，计划包含叙事及视觉方向；生成时展示动态页面网格，已生成页面可先查看，局部修改应保留其他页面与手动编辑。这些是官方承诺的产品行为，不能据此证明某个调用的并发方式。[官方Agent创建流程](https://help.gamma.app/en/articles/15002203-how-do-i-create-with-agent-in-gamma)

**对本模块的新增建议（D）：**

1. 保留用户已经确认的手动“读取并估算”流程；不能为了模仿Express跳过来源阅读与大纲确认。
2. 计划确认应覆盖叙事目标、信息取舍与视觉表达意图，不能只让用户看标题列表。以可折叠逐页说明避免主流程信息过载。
3. 如果将来支持快速入口，它是交互确认次数的选择，不能与fast/balanced/rigorous模型执行策略、内容详细度混成一个“质量”开关。
4. 生成UI验证“已开始/已完成页面可以查看”，不因官方动态网格说明就假定文字是逐token流式；文字/图像/布局实际更新顺序需本轮网页实测。

### B02：原样导入、来源重组与摘要是不同合同

官方导入说明区分保留既有设计与用内容重新创作；Classic有Generate/Condense/Preserve，新Agent可用自然语言指定处理方式。保留模式不能等同精炼摘要。[官方导入及文本处理说明](https://help.gamma.app/en/articles/11047840-how-can-i-import-slides-or-content-into-gamma)

**对本模块的新增建议（D）：**

- 引用模式/摘要选择是来源处理合同，详细度是解释深度，两者独立：标准深度不应自动触发全文逐字保留。
- 已有的合同、深度与来源规则应在brief中合并成清晰摘要，不新增一组与旧字段打架的控件。
- 目标是教学编辑稿时，不把长教程当短主题再随意扩写；也不按Preserve的字面保留要求评价Condense稿。
- `.md`入口兼容性不能从官方列出的PPTX/DOCX/PDF推断；本输入先尝试全文粘贴或界面实际支持的文件入口，不擅自转换后宣称原文件直传成功。

### B03：Gamma 5并非仅有可伸缩卡片

官方布局文档说明Gamma 5采用固定16:9画布、比例网格与自由定位。固定模式会在可读下限内缩放以适配；fluid模式保持内容尺寸并增加高度，旧稿保留既有行为。自由定位块不随周围网格重流。[官方网格与自由定位说明](https://help.gamma.app/en/articles/17572896-how-do-grids-and-freeform-editing-work-in-gamma)

**对本模块的新增建议（D）：**

1. 修正“Gamma无需容量检查/总能向下增高”的错误对标前提。固定页仍要测量文本、组件内部与导出结果。
2. 自动排布区与用户自由定位区在IR中明确区分。沿用用户锁定/命令日志语义，AI重排不能拉回用户手工摆放元素。
3. 网格布局应支持组件所在区域的比例变化，连同内部文本与图例重新测量，而非只缩放截图或外框。
4. 模板对齐、编辑器预览与导出共用可见scene合同；不能UI重流一次、exporter再凭另一套规则排一次。
5. 不因为竞品支持一定缩放就放开本模块字号。按用户已确认的“小幅缩小且设置可读下限”执行；超出政策则保留草稿并请求调整展示范围。

Classic的布局资料介绍时间线、列、画廊与一键换版；新网格资料说明Gamma 5将经典独立布局形式归并到网格系统。应分别记录账号当前入口，不拿旧版菜单作为新版必有控件。[经典布局说明](https://help.gamma.app/en/articles/11029130-what-s-the-fastest-way-to-transform-content-and-layouts)、[Gamma 5网格说明](https://help.gamma.app/en/articles/17572896-how-do-grids-and-freeform-editing-work-in-gamma)
