## 内容提取与语义分割

| 重点 | Gamma | 本轮 DL 37 页候选 | 结论 |
|---|---|---|---|
| 金融低信噪比与复杂度预算 | 2–5 页形成紧凑论证 | 2、4–12 页拆得过细，5/6、9/10、11/12 为双语单元译成英文后的重复 | 单语下应先审查语言对等价，再只分配一次可见主讲归属 |

| MLP 与浅层/树基线 | 第 7 页给层数、宽度、dropout、L2、ensemble | 19/20、21/22 再次重复；细节更完整但阅读收益小 | 不应按原语言单元逐页生成 |
| RNN/LSTM/GRU 与按日期训练 | 第 8 页讲失败原因及修正 | 23–27 页含完整门控公式、训练配置和 batching；26 页左右英文重复 | 公式细节可按明确 overview/notes 合同安排，关键训练条件必须主稿可见 |
| Qlib 表格 | 第 9 页：5 个模型及 IC 范围 | 第 28 页有同类表格、完整解释，范围保留 | 表格是实质优势，但不应重复添加“摘要表”标记到所有未删行表 |
| Transformer / CNN / GNN | 第 10 页按输入几何组织 | 30–31 页有机制/限制，空间利用低 | 按“输入结构→模型→适用条件”形成同一比较页 |
| 训练纪律、HIST/TRA、A 股、完整实例 | Gamma 10 页未同等展开这些扩展内容 | 29、32–34 页覆盖更多，但还需检查摘要是否遗漏或改写条件 | 不能用 Gamma 的页数作为完整原 input 的硬上限 |
| 收束与叙事顺序 | 第 10 页以架构选择收束 | 35–36 页决策/纪律后，37 页又回到 ALSTM 公式 | 尾部遗漏修复应插入所属章节，不能追加到结尾破坏收束 |

Gamma 的主要优势是每页一个判断，2–4 个语义块组成阅读路径；它没有把每段来源或每种语言都视作独立页面。当前候选的完整性约束较强，但“来源对象完整”与“读者需要一页新信息”的映射仍不够好。

## 内容排布与视觉证据

所有 10 页 Gamma、37 页 DL 候选、30 页 QuantPilot 候选已渲染并逐页查看。

- Gamma 的标题、短卡片、表格和重点数字形成清楚层级，留白服务于主旨。照片/插画多数是气氛与装饰，不能将其全算作事实图解。
- Deal Review 候选保留原字体和装饰构图，但部分页面仅一段短文，多个章节可共享一页。模板装饰占据固定区域时，容量不足应先选合适原生版式，再决定续页。
- 部分公式被水平铺满或放在深色块中，对比与尺度不理想；字符存在检查不足以保证公式可读。需要额外检查公式纵横比、对比度及与变量解释的关联。
- QuantPilot 目录现在包含真实页码且字体未缩小；封面原生标题框使用上方空白扩展后通过实际 PDF 字形检测。
- QuantPilot 第 10 页把“现有数据”和“排除/仅研究的数据”并排呈现却缺少限定标签；第 12/13 页的 LLM 使用限制重复；第 15 页“from→into”关系表达不完整。整稿审查必须阻止这些内容发布。
- 候选中少量标题和说明混入中文，而原正文为英文。语言规则必须在大纲 metadata 修复、writer、critic 中使用同一策略。

## 本轮已实施的相关修正

1. 全局章节/核心消息账本进入每个规划分组；短相近内容提示合并；短稿同样检查重复核心消息，真实不重叠表格续页允许保留相同主题。
2. V2 局部失败取消全量重写回退；metadata、来源去向/归属、关系、容量与 writer 修复保留无关页面。
3. 目录独立规划短标签并做语义审查，最终页码按稳定 slide ID 派生；审查器获得真实页码账本，不把系统目录当作无来源数值。
4. 单语 overview/notes 的结构化语言对增加独立完整等价审查。只有条目、数字、顺序/关系和限定均对应才允许可见一次、两份原文进备注；负面或过期审查不能允许去重。新一轮真实审查已有 7 组清单全部通过，经来源归属和实际字号容量修复后，**29 页大纲通过门槛**（全部 29 页量测，0 页溢出）。19 页只是一度出现的未通过候选；29 页相比 37 页少 8 页，但最终正文质量仍待验证。
5. 审查格式改为平铺的 ID/quote 引用，服务器继续验证精确三元组和每项义务。独立批次最多并行 2 个，成功批次保留检查点；不把模型 transport/400/timeout 改成通过。
6. 审查提示区分 source 双语保留与 explicit output 单语策略；正确同义表达可通过，限定遗漏和实际重复仍需报告。
7. 真实 QuantPilot 的错误 claim 引用现在只触发该条审查，修复请求从约 146 KB 缩至约 4 KB，其他已验证批次保留；随后整稿审查已完成并进入具体页面修复。这是协议稳定性的实测改善，尚不能代表最终内容合格。
8. 修复提示追加诊断后，selection/navigation/writer 的内嵌 JSON schema 仍被完整保留；此前把诊断一起当作 JSON 解析会丢失响应约束。允许的语言对应目标也收敛为明确枚举，相关定义不能冒充真正的对应正文。

## 后续必须达到的质量目标

| 优先级 | 改进 | 验收依据 |
|---|---|---|
| P0 | 语言对在大纲分配前去重 | 双向独立审查 + 原文备注 + 全部必要条件可见；同一英文核心消息不主讲两次 |
| P0 | 局部补漏回到原章节 | 稳定来源归属和问题账本定位；总结后不追加无关公式 |
| P0 | 条件与对象共同规划 | “included/excluded”“from/into”等关系有可见承载者；不能只保留名词列表 |
| P1 | 按最终对象密度合并短页 | 同一问题的短定义/公式/条件合为一页，原字号不变、完整对象不丢；确认前展示最终数量 |
| P1 | 公式视觉检查 | 纵横比、字号、对比度和变量关联都通过实际渲染检查 |
| P1 | 语言策略一致 | 英文输出的标题、导航、正文和局部修复均使用英文；专名例外可追溯 |
| P2 | 语义图解代替部分装饰 | 模型选择矩阵、数据流、验证流程体现真实关系；图片数量不作质量代理 |
