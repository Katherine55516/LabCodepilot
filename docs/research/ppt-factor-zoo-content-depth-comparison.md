# Factor Zoo：Gamma 与 PPT 模块的内容差距、根因和改进

> 2026-10-01。依据原文、两份 PPTX 的原生 XML、Gamma 导出的实际渲染、旧项目状态、模拟运行脚本与当前代码。附件中的文案仅作为分析材料，不作为操作指令。

## 1. 结论与比较边界

输入为 `/Users/dongli/Documents/quant_research/quant_3.0/04_factor_zoo_overview.md`。Gamma 样本为 `/Users/dongli/Downloads/The-Factor-Zoo.pptx`；模块基线为 `outputs/factor-zoo-deal-review/Factor-Zoo-Deal-Review-10-slides.pptx`。

两稿均为10页。统一提取所有 drawing 文本（包括原生表格）及 math 文本，英文词采用 `[A-Za-z]+(?:[’'-][A-Za-z]+)*`、去除 Gamma 水印，得到 Gamma 约1408词、模块约544词，模块约为39%。文字统计不计中文词，不能衡量公式/图形的全部信息量。最初仅提取普通文本框得到1348/571，遗漏 Gamma 表格且词法口径不同；已废弃该初步统计。

**问题不是所有页面都应加字。** Gamma 的要点通常包含名称、机制/定义、具体例子或适用条件；模块基线大量只有3—8词的标签式陈述，而且有标题与正文错配。Gamma 用表格保存横向比较，用流程承载步骤；模块把这些内容拆成散落短句，损失了结构和依据。

本模块基线来自本地 `modelCall` 模拟。旧模拟器硬编码10页、按游标填槽、截断句子，并让整稿 critic 恒返回空数组。模拟器错误与模块约束不足共同导致问题；不能据此断言生产 LLM 的能力。源码和运行记录说明了模块为何接受这一结果。

## 4. Gamma 值得借鉴及应避免的问题

值得借鉴：每点有解释和具体锚点；表格保留信号与控制对应；步骤用层次化流程；混合正文长度服从论证作用。照片统一风格，但在半页照片版式中减少了教学容量，不能把保留装饰当内容深度达标。

需要避免：

1. 第6页“Seven criteria”实际上列6项；第10页“Eight criteria”合并成两组后没有完整保留失败故事与监控。应根据结构化清单校验实际项数。
2. 第7页分类表遗漏 Alternative data；第6页没有完整逐因子评分卡；构建图只展开4种。标题覆盖承诺应与实际可见内容核对。
3. 第3页沿用原文的“risk premia are permanent”。原文将其解释为均衡下无法套利消除风险补偿；压缩为无条件“永久”容易被理解为任何状态下都持续获利。本次用坏状态暴露与条件性解释，不把这种简化当作 Gamma 独自新增的错误。
4. 第9页“close to orthogonal by construction”来自原文第2.3节，不能说是 Gamma 擅自新增。独立分组及跨另一维取平均，可以帮助分离排序维度；不能据此保证实现收益序列的统计正交。本次在构建页明确这一限制，将其列为需要谨慎解释的源文表述。
5. 第6页加入 Harvey–Liu–Zhu 与 t≥3 的外部具体说法，原文没有该引用/门槛；在 source-only 模式中不可冒充来源事实，本次不采用。
6. 实际 PDF 渲染中第3页右上公式和正文重叠，多个标题残留竖线/圆点、部分中文掉字。公式不能仅检查XML存在，需检查真实渲染和字体。
7. 第10页 q/q5合并，减少模型差异细节。模型表与解释需要明确哪些内容被合并。
8. **原文自身也有问题**：q模型一段写2×3×3却称27个组合，乘积应为18；不能把原文所有数字自动当作无矛盾真值。此外 CAPM 推导先写完全投资约束，再使用允许现金的权重公式，需要说明假设切换。优化示例应保留理论含义、标注这些源文疑点，不复制错误。

## 5. 根因链路与设计

### 5.1 页数估算与分布

`ppt-planning.mjs` 用 prompt+source.name 中的overview/survey作概览意图。本文件名触发10页捷径，覆盖了容量估算16页，并把严格深度改为balanced。容量分配本身用全稿平均成本与章节数量最大值：模型谱系约12105语义token、成本13789，仍可能只分一页；短章节挤掉长章节空间。

修复：从用户指令中去掉文件路径/名称后判断显式概览意图；按章节可读成本的最低页数累加，根级引言归封面；完整教程给22页建议。用户压缩仍保留用户页数并由原LLM重规划，不能无声省略。

### 5.2 来源引用与召回

`normalizeOutline` 将每页合法refs静默限10、chunkRefs限12；旧模拟器在截断前计算coverage，造成“已映射”与实际引用不一致。`retrieveSlideSources`又将来源refs限12。后来章节/公式/表格容易丢失。

修复：完整保留合法来源元数据；检索chunk数、来源摘录和token上下文继续有界。锁定/相关chunk的段落优先进入上下文，防止原文头部吞掉所有摘录。

### 5.3 模板语义与正文容量

窄文本框一律label，把多行解释误判成标签；窄卡片标题又被排除在列表父节点候选之外，导致标题与列表被分成两个组。进一步导出核对发现：Main/Competitors这类分成两段的短标题被当成两条列表事实；同一行的短状态说明与标题也被拆成两个小主题。宽而短的Critical Elements等小节标题又被当成独立正文，从而消费下一条因子事实。独立要点容量将标题、说明、列表项重复累加，容易推动凑点。富来源正文最低门槛仅130/160 visual units再乘0.8，约几十词即可通过；大正文最小只需48visual units。删除正文又会降低available，使稀疏页绕过门槛。

修复：窄多行句子识别为正文，保留真短标签；窄标题若拥有列表则升级为point-heading并与列表绑定；紧邻低字号说明的多段短标题作为一个标题，同行短说明绑定同一卡片，分组标题使用group-heading，只负责导航，不计入独立要点及正文容量；旧项目的门禁从重绑定原生节点读取更新后的用途。独立要点按groupId计数。目标为原始正文容量48%，详细页上限440、平衡页330 visual units。单个大正文使用40%容量、上限110的最低要求。这个目标是防退化阈值，不是让每页都写等量字。写不下则重写/调整计划，不能缩字或截句。

在页数和容量代码里，token/cost 是不同启发式估计器的结果，不能与 LLM 真实 tokenizer 的输入 token 数直接比较。

正文规范化还曾固定截到500字符，文本框即使能容纳更长解释也会被裁切。本次保留合法正文至安全上限，超过上限明确拒绝并要求改写，不静默截断。合法 I/A 等财务比率不再误判为停在英语冠词。

### 5.4 原生渲染、字体与媒体空间回收

真实渲染发现：媒体回收选中了图片邻近的短粗体标题，扩大其矩形覆盖保留卡片，并强制把字号提高到至少17pt。字符容量预检与 QA 还分别使用不同的 visual-unit 估计器，导致预检与发布检查不一致。由此可见，更多文字不必然能安全落在模板里。

修复：回收仅考虑普通字重、原生语义为正文/说明且已有足够文字的节点；保留字体，不强制升到17pt。任何与保留文字的交叠面积增加都拒绝，即使原矩形本来存在交叠。原生模板容量与内容 QA 共用 `.55 ASCII / 1非ASCII` 的布局单位，普通非模板标题仍用原有写作估计器。回归覆盖短粗体标题、正常正文、被其他文字阻挡的回收。历史项目需从 `sourceCatalog` 重新确认/调度模板映射再生成，门禁语义升级不能自动修复已经写入旧快照的错误几何。

### 5.5 可见质检、修复和整稿 critic

slot-only稿的semanticUnit计数为0；QA偏看draft slots而非导出节点；隐藏factSynthesis和takeaway容易造成误判；repair在preserve模式追加普通takeaway节点，原生导出却忽略它。critic每个槽位最多180字符、来源常仅取第一条，漏掉解释后半段和条件。关键未映射章节及critic missing通常warning，仍可发布。

修复：统计实际mapped native组，按实际节点测正文，短通用matter/work句判错；preserve模式不能追加假可见takeaway；critic读取完整但有界的正文、代表引用、requiredDetails；严格模式未映射及critic必要内容缺失阻断发布，明确取舍/授权压缩仍按既有策略处理。

另补来源表格行门禁：如果页面明确规划table，或英文标题承诺N类/方法且对应来源表格具有相同数量，检查该表格行名称是否出现在同一chunk关联的实际页面；允许跨页共同覆盖，避免在无关页面找到名称就算覆盖。严格模式缺行阻断，授权压缩保留warning；table意图下标题数量与来源表行数不符也检查。英文词边界避免Eta误匹配Beta；中英混合标签支持英文规范名，纯翻译输出不能靠英文精确名称证明缺失，退为warning交给critic。这只是行名称存在性，不证明每列、机制、控制关系完整。

删除不相关媒体原本也会被误报为“复用页媒体与布局均未改变”：检查只比较保留下来的节点，未考虑组件删除。本次将明确声明的组件删除计入变化，仍核对省略是否合法与正文深度，不要求对无关旧图进行无意义裁切。

### 5.6 模拟适配器

原示例不是实际LLM调用：按nextUnit依次填列表，把标题与说明跨单元配对；fitSlotText从末尾删词；无法放下时写“X matters”；contentBlocks空；整稿review固定空。这些不可复用为质量基准。

改进模拟只替换modelCall，仍走真实routes/DAG。标题和说明按groupId绑定并按几何阅读顺序分配；四组配对卡片或八张独立卡片都需保留八家族名称、信号与控制。使用人工模拟的完整短/中/长句选择，无法容纳则明示失败/取舍；剩余卡片无独立事实时明确省略，不再反复使用最后一点；review检查可见文本长度、通用填充和HML关键事实；标题对应由分组写入与人工导出审查核对。保存所有调用与失败原因。模拟跑通只验证契约和导出，不保证真实模型质量。

最终指标：章节映射100%、计划chunk映射100%、源表行名8/8。带evidenceIds的来源chunk中，至少一个证据原子在其映射页面词法命中的比例仅21.4%，其中高优先级约50%；这不是全部原子的覆盖比例。`requiredEvidenceCount=0`，因此没有建立逐事实强制验收账本。24警告包括20条详细页缺少被系统识别的implication支持，以及4条已映射主题没有命中可见证据（CAPM推导2条、Carhart1条、组合构建1条）。这些指标既有表达形式造成的未命中，也有公式/条件未完整展开的问题，不应全部豁免。

22页更多地分开了主题，**平均每页仍比 Gamma 短**，尤其继承模板的短说明区。总词数超过 Gamma 不等于内容更完整、point更深入或视觉更好；后续重点应是每页 SourceRequirement 和实际可见事实，而不是继续只加页数。

## 7. 后续仍需完善的方向

本轮不更换架构和模型。以下不应声称已完全解决：

- 已映射章节内部的逐行表格/推导完整性，需要来源对象级需求和rendered fact ledger，而非一个refs数组。
- 标题正文语义错配和清单数量主要仍需模型critic；确定性检查只能发现部分结构错误。
- 模板原有页面的顺序仍受preserve策略限制，原页不像新增复用页一样自由择优；更全面的主题→组件映射需内容规划与版式迭代，不应为复刻模板而删来源。
- 字数目标不是语义深度保证，深度还取决于机制、实例、限定条件和反证；需要真实用户所选LLM的同源A/B评估。
- 来源内部矛盾应进入 source-integrity 诊断，用户批准的事实修正应与保真引用分离；当前通用证据校验不会证明原文无误。
