## 3. 语义模型、描述和逻辑评审

### 3.1 Gamma 的优势

参考稿用“一个读者问题 + 若干不同的支持块”组织页面。每个块有作用：定义、机制、例子、条件、后果，而不是每个源段落独占一页。第5页将 Brief、IR、Layout 和 Theme 连成解释链；第9页把公式嵌入性能机制，读者无需自行拼接四页信息。标题大多直接命名主题，短描述支持实际内容。章节相近且短时合并，主要内容层级比 source heading 更重要。

### 3.2 module 的根因

1. 唯一来源归属被过度物理化：来源主讲不能重复，并不意味着每个来源对象须独立一页。
2. 大纲预算虽已有压缩提示，后续原生组件容量分片仍可能放大页数；字段表、完整流程、定义与实例的关联需要在选择与布局之前联合规划。
3. 原始标题顺序、来源 batch 与模板槽位影响叙事过大。模板容量是约束，不能成为读者主题。
4. 同页事实保全能力较强，但生成解释过长，概述、定义、备注支持和局部修复相互反复补充。
5. 旧版使用“结构字段示例见后续页面。”维系跨页结构，曾因此被门禁阻止。现在已派生实际字段与页码，但第10页→第11页的坐标表说明：目标存在不等于语义相关，还需排除对照对象被误称为定义示例。
6. 质量审查必须同时看到实际跨页片段、已授权备注与 source-only 证据限定。局部失败只修改局部，不能借修复重写正确页面。

### 3.3 Gamma 也需要保留的限定

- 第5页 Brief/IR 内部设计与第7页 source of truth 属架构推断，参考措辞比输入更确定。module 应保留“推断/很可能/未公开”。
- 第4页保留 fast path，却没有明确保留新 Agent 因规划研究可能慢于旧生成器的条件，不能按参考删掉该条件。
- 第8页只列主要 workflow，不是原始16行完整覆盖。notes 合同可以采用任务族概览，但不能宣称主稿显示了全部原表。
- 第9页“无需 Screenshot QA”过于绝对。输入解释的是 native reflow 可减少循环，不足以证明任何场景都无需视觉验证。
- 第10页标题说10条原则，正文实际只有少量合并段落。设计原则可组合，但计数必须与实际可识别条目一致。

### 3.4 目标语义模型与实施边界

主要差距在编辑层：来源被完整保留，却没有充分分配主张、机制、例子和条件的轻重。参考稿让读者在一页内完成一个理解任务。module需要把这些职责显式建模，再进行来源选择和容量分配。

| 层次 | 应保存的语义 | 当前实现与边界 |
|---|---|---|
| 整稿 | 读者目标、问题组顺序、各主题唯一主讲归属 | 本次新增真实全局问题组；来源全覆盖与关系校验是确定性约束，问题是否真正互补仍需语义评审 |
| 单页 | 一个核心消息，定义/机制/实例/条件各有增量 | 现有focus、question、typed contentBlocks与必要条件合同；不能用“每个对象一页”替代编辑判断 |
| 证据 | 主张指向原始单元，推断程度、否定、因果与单位保持 | 原文、selection ledger、claim/obligation audit继续保留；引用ID本身不能证明正确 |
| 细节 | 明确区分核心解释、代表示例和完整原件 | 本次开放有界字段行摘要；原表进备注，不把随机单行当作完整比较、不改原始值 |
| 关系 | 顺序、并行、分支、对照、层级分别表达 | 解析器已有关系类型；本次纠正几何对照表被用作IR示例。ASCII关系到高质量可编辑图的呈现仍是未全部解决的后续工作 |
| 分页 | 实际读者问题和真实可读容量；续页有新信息 | 全局语义组先于批次，实际字号/容量门禁随后验证；估算可重分配，原始来源和显式页数不因估算而改变 |

## 4. 改进方案（先记录、再执行）

### P0：具体而有来源的页级组织

- 全局规划增加读者问题、主张、支持单元角色、关系类型、条件和增量要求。先进行这些判断，再分配来源 ID 与原生容量。
- 同一 semantic chunk 的定义、字段/schema实例、因果解释优先同页。需要续页时按完整对象/连续字段区间保留，第一页不能仅留下抽象定义和制作提示。
- 性能等因果解释按“现象/成本→机制→模型→条件”排列，不照搬 stale heading 或 source batch 边界。
- 跨页 schema 导航由实际显示字段与 stable slideId 派生，文本直接列明对象/字段及页码，不使用“后续将解释/见下一页”的承诺文案。来源和页码验证仍保留。

### P1：预算与内容形态

- 概览稿不自动占用目录页。长稿或用户要求仍可配置目录；已确认页数不改变。
- 对 overview/notes：短段落按语义摘要；保留定义、数值、条件与未知边界。完整次要实现示例保存在备注，不把每个字段拆为独立页。
- 不强制所有页面四卡片：关系型系统用分层/并行结构，比较用共同维度表格，流程按步骤族，结论用可执行设计决定。
- 拆页之后检查首/末片负载和增量；不足容量不通过缩小模板原字体或删除字段“解决”。

### P2：门禁与实测交付

- 当前27页项目局部修复后继续真正 LLM review 和原生导出，保留现有完成节点。
- 新规划规则做专项回归：自动目录选择、同源字段导航、跨页不借用其他来源、明确页数不被预算覆盖。
- 最终 PPTX/PDF 逐页视觉验收，检查字体、正文、公式、链接与完整原始输入备注。
- 若仍被真实门禁阻止，交付明确标为诊断的稿件与具体失败记录，不冒充完成或关闭 threshold。
