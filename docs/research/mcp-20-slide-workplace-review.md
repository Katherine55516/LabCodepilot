# MCP 20 页示例：职场汇报内容评审

评审对象：`outputs/mcp-full-chain-gamma-template-20-slides-simulated.pptx`。输入只有一页 MCP 完整链路 PDF（提取文字约 1,939 字）；大纲、页内容和整稿评审由测试脚本模拟 LLM，原生模板渲染、PPTX 导出和确定性质量门禁走 PPT 模块。

## 结论

可作为 **MCP 链路内部讲解初稿**，尚不能作为可直接交给管理者或跨团队评审会的 **职场决策报告**。20 页 PPTX 可打开、保留了 Gamma 模板的原生图片和组件，质量门禁无硬错误；然而 `passed_with_warnings` 只表明程序规则通过，整稿模型评审也由空数组模拟，不能代表内容经过人工或真实模型审校。

## 逐段观察

当前页数分布为：铺垫（2–10 页）9 页，占 45%；5A 2 页，占 10%；5B 3 页，占 15%；5C 4 页，占 20%；封面与结论各 1 页。读者要到第 11 页才看到第一条具体路径，而原始输入是一页完整流程图。

| 页码 | 当前作用 | 主要问题 | 调整方向 |
| --- | --- | --- | --- |
| 1 | 封面 | 只有“MCP 完整链路”，缺少受众、用途、日期及来源 | 写明“5A/5B/5C 如何选路”的目标和适用场景 |
| 2–5 | 参与者、发现、能力清单、缓存 | 9 个内容页中的前 4 页被基础概念占用；第 2 页“五类参与者”与图中文字中的更多标签不够一致；第 5 页有被容量裁短的短语 | 合并为角色总览、发现与缓存两页；每页保留一条决策相关结论 |
| 6–10 | 用户输入、资料包、外部需求判断、内置能力、Server 选择 | 结论多是名词标签，判断条件散落五页；没有一张真正的选路总览图 | 用一页“是否外部 → 内置或 MCP → 5A/5B/5C”的决策树，再用一页讲 Host 规则与权限 |
| 11–12 | 5A Tool | 请求和返回被拆为两页，缺少可核对的参数示例与异常路径 | 合并为“触发条件 → 请求 → 返回/错误”一页，必要时附一个来源支持的示例 |
| 13–15 | 5B Resource + Tool | 同一原则在“别名、缩写、歧义、归一化”之间重复；读资源、调用工具拆得过细 | 合并为条件页与顺序页；展示归一化前后参数的差异 |
| 16–19 | 5C Prompt 工作流 | 四页讲 SOP、执行与 report 模板，篇幅超过 5A/5B；图片和半环形图保留了模板视觉，但不是 MCP 协议图 | 压为 2–3 页；用真实的 `prompts/get → resources/read → tools/call → prompts/get` 时序图 |
| 20 | 三条路径总结 | 列出选路条件，但没有决策建议、适用边界、责任人与下一步 | 增加默认推荐、例外条件、验证清单和待确认问题 |

## 必须改进的内容规则

1. **先定报告任务**：输入受众、要作出的决定、汇报时间与“仅依据附件图”的证据边界。若只有单页流程图，系统应提示 20 页的重复风险，允许用户保留页数，但把新增页显式安排为示例、异常与附录；不能靠改写同一事实填满页数。
2. **以结论式标题替代主题名**：例如“参数可直接确定时走 5A Tool”“参数含别名时先用 Resource 归一化”，标题与正文的判断条件一一对应。
3. **保留源图的信息结构**：至少有一页五泳道完整链路、一页 5A/5B/5C 选路决策树。建筑照片可继续作为装饰，但不能代替说明调用关系的图。
4. **每页一个主张和相应证据**：把 PDF 中的调用名、触发条件、返回类型及 Host 可选策略对应到页内；明确哪些是示例，避免把某个 Host 的实现写成协议必然行为。
5. **限制复制和碎片化**：同一触发条件在主文只完整解释一次，其余页面引用或进一步讲异常/实现。单页流程不应在没有额外来源的前提下拆成多页同义描述。
6. **提高可读性**：对模板中 8–10 pt 的密集版式只放短标签或附录，不把汇报正文塞入小字号框。质量规则应增设“演示场景最小字号/可读距离”检查；当前 41 条图片分辨率警告来自模板素材，公开汇报前也应复核。
7. **建立可见的来源与局限**：在相关页或尾页标注“来源：09-MCP 完整链路图（含分支原因，单图版）”，记录原文位置；缺少真实案例、性能数据和组织策略时标明待验证。

建议在保留 20 页硬参数的情况下，将主文控制在约 12–14 页，其余用于可验证的调用示例、错误路径、Host 策略清单和术语/来源附录；若没有这些补充资料，优先建议用户把页数降到 12–15 页。
