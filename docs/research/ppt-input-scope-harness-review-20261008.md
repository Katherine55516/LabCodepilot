# PPT harness 输入框架约束评估与修复

> 2026-10-08；评估当前工作区代码，包括此前尚未提交的渲染契约修改。本轮只修改内容约束、审查、版本绑定和相关测试，不更改 UI、创建步骤或页数算法。

## 结论

原 harness 已经限制工具、JSON、编辑目标、来源数字、必要证据与媒体结构，但“遵守 input 的内容框架”主要依靠自然语言约定。无数字的越界主题、模型规划出的额外议程、修复建议带入的新事实，仍可能通过格式和确定性质检；整稿四个空 findings 数组也不证明做过范围检查。

已把原始输入作为单独的 INPUT_FRAMEWORK，收紧可补充内容的含义，要求整稿逐页 scopeAudit，且在局部 AI 内容提案持久化前检查范围。遗漏、过期或伪造标识的审查不能成为发布通过依据。输入不足时保持事实边界；自动页数路径可以减少页数，不能靠重复、外部事实或模板故事凑密度。

这不是“模型永远不会生成越界草稿”的证明。规划/逐页生成仍可能产生有问题的草稿；最终生成发布和局部提案保存有审查门禁。本轮验证了协议、失效机制和拦截逻辑，未测真实所选模型的语义误判率。

## 审计范围与发现

| 路径 | 原风险 | 本轮处理 |
|---|---|---|
| routine-runner → PPT 模型 | 原本已关闭工具、MCP，使用 PPT 专用 system prompt；但禁止编造不等于限制主题 | 保留无工具 harness；system prompt 明确只展开输入已有主题，禁止自定议程与事实前提 |
| 纯 Prompt | `source_plus_explanation` 对通用机制、对照、示意情境的许可较宽 | 对外兼容原枚举，Prompt 改为 bounded_explanation；仅允许理解已有主题必需的定义、关系、条件 |
| 来源/文件/粘贴 | `brief.sourceScope`、ownedPoints 是模型产物，可能自行扩大输入解释范围 | 原始 prompt、完整来源文本/segments、来源对象和图片说明形成框架；brief、计划与引用 ID 不具有新增事实授权 |
| 密度/详细模式 | 容易把“有完整解释/更多信息”理解为必须填满模板 | 明确详细模式只加解释深度；不能虚构角色、时间表、数字、结论，也不能增加无关主题 |
| 写作示例 | 示例补入了“已约定检查标准/必须记录责任”等给定事实中没有的信息 | 改为由给定事实直接支持的解释，继续标明示例不是本次材料 |
| writer/局部编辑/title/typed/legacy rewrite | 多处把局部 instruction 拼入 project.prompt；共享政策可能把编辑需求认作新输入框架 | 去除拼接；编辑指令单独传递，翻译用显式 local language override，事实和主题框架不变 |
| critic/repair | 四类 findings 没有强制逐页范围审查；只查数字不能发现定性越界 | unsupported 同时覆盖 out_of_scope、unsupported_fact；repair 仍共用原框架，建议不是新的来源 |
| 整稿上下文 | 非原生文案截到 500 字；长稿原生槽位数量与文本预算裁剪；静态模板文字可能不可见于 critic | 保留完整可见 canonical 内容、原生静态/未映射文字、表/图数据与图片说明；隐藏内容和过时 bullets 不充当实际可见内容 |
| AI 提案 | 确定性 gate 通过后就能保存/应用，没有独立内容范围检查 | 内容/title、AI data/structure 候选审查通过后才能保存；无模型、未完成审查、越界或冲突返回 422/503 |
| 外部 PPTX | reviewSemantic 遇到 externalPptx 直接跳过，AI 后可能不重新审查 | 删除豁免；真正作为输入导入的 PPTX 保存原始文本/表/图基线；作为设计模板使用的 deck 不成为项目来源 |
| 审查与提案缓存 | 来源 SHA 存在时 prompt 变化未单独进入 review key；提案缺少内容审查版本绑定 | frameworkHash + generationPolicy + v7 进入 plan/review key；scopeAudit 必须匹配当前输入与全部 slide IDs；提案绑定实际改动页的候选内容 |

## 可补充与不可补充

| 输入类型 | 允许 | 禁止 |
|---|---|---|
| 简短主题 Prompt | 为该主题补必要定义、关系、条件；保持原目标与范围 | 临时增加另一个主题、品牌案例、实测结果或数值 |
| 长研究/课程文稿 | 重组章节、展开材料已有机制、解释变量和限制；必要的框架内说明 | 引入材料外的研究结论、论文年份、数据集成绩或默认投资建议 |
| 业务材料 | 清楚说明给出的问题、证据、决策条件与责任关系 | 自行安排负责人、截止日期、承诺收益或“下一季度策略” |
| CSV/表/图 | 保留类别、关系、符号、单位和条件；解释数据表达的含义 | 造新行/新指标、把估计改成实测、凭空推出因果关系 |
| 代码/架构/流程 | 解释输入中已有接口、步骤、分支、依赖；原结构不因 prose 丢失 | 发明系统组件、供应商、性能提升或不存在的执行步骤 |
| 双语/多语 | 改写、等价翻译、保留术语与事实对应 | 借翻译增删主张或把两个语言版本当成两份新证据 |
| 图片或信息稀疏输入 | 使用可靠说明；保留未知与限制 | 从装饰图片、模板截图或缺乏识别证据的视觉猜测构造事实 |

`source_only` 不新增事实前提，只解释已有事实与关系。`source_plus_explanation` 可增加理解原主题必需的背景说明，必须锚定原主题；示意例子须明确为示意，不能伪装成真实案例或实验。两种模式都禁止越出框架。完整度和密度不能覆盖这项约束。

局部用户输入“加一个无关主题”会成为范围冲突；若确实要改变事实来源或主题，需在输入工作流更新材料。它不能通过“优化标题/展开解释”暗中改变整个项目的输入范围。

## 代码落地

### 输入框架

`apps/cowork-server/lib/ppt-input-scope.mjs`：

- `inputFramework(project)` 独立于 model brief、模板示例和当前生成 deck。
- 保存完整 prompt/source 文本、segments、结构对象与媒体说明；旧版本更新使用 baseSnapshot 的原始输入。
- 真正导入为内容输入的 PPTX 使用 `importedInputScope`。这是原始输入基线，不随着编辑后的 deck 自行重写。
- SHA-256 是输入版本标识，不是语义正确性的证明。
- shared `promptPolicy` 向 planner、writer、repair、critic、edit 传递同一套规则与框架。

### 必须完成的审查协议

保留既有 `missing/repeated/conflicts/unsupported` 四个数组，另要求：

```json
{
  "scopeAudit": {
    "frameworkHash": "当前 INPUT_FRAMEWORK 的 SHA-256",
    "checkedSlideIds": ["所有真实页面 ID，且每个只出现一次"],
    "status": "complete 或 not_evaluated"
  }
}
```

`normalizeModelReview(..., project)` 在生产路径严格检查审查字段；缺失 hash、错 hash、遗漏/重复/未知页 ID 或非法状态会报错。`not_evaluated` 即使四个数组为空，也会阻止发布。无数字的越界话题放入 unsupported，reason 可为 out_of_scope；来源不支撑的具体事实可为 unsupported_fact。

这一步要求审查实际对照输入，而不是确认 writer 声称的 sourceScope。没有逐字引用的正确释义不会用关键词相似度误拦；有一个合法 source ID 也不能证明整句内容真实。

`PPT_PROMPT_CONTRACT_VERSION` 与 `REVIEW_RUBRIC_VERSION` 升为 7；输入、prompt、政策、内容或可见性变化使旧审查失效。整稿复审仍在既有 review→repair→publish 节点内，不增加用户步骤。未完成或不合法协议不会退回默认空报告通过。

### 局部候选与应用

`ppt/input-scope-service.mjs`：

1. 比较实际语义内容，确定改动页；纯位置、样式不增加内容审查调用。
2. 对 AI 内容、title、data/structure 候选调用用户所选模型审查。
3. 只把原项目 input 当作来源；候选自身与 instruction 不授予新增事实权限。
4. 改动页的 unsupported/conflicts 或未完成审查阻止保存提案；已有质检仍处理数字/单位、结构、容量和必要证据。
5. 保存 frameworkHash、changedSlideIds、候选内容 hash。应用时再核验，旧/被改动/失效提案必须重新预览。
6. 仅绑定实际改动页，保留已有“其他页修改后仍可应用目标页提案”的并发语义；最终发布仍审查整稿。
7. 局部翻译的显式 language override 传给候选审查，不变更原框架。

已有 legacy rewrite 也接入候选审查。生成中的逐页草稿仍由最终整稿门禁兜底，并保留两轮有界 critic repair；不改既有暂停/恢复、范围冻结、epoch 与用户保护机制。

## 验证结果

测试证据位于 `outputs/ppt-input-scope-harness-20261008/`；最终汇总见 `backend-results.json` 和 `npm-test.log`。

- 全部 31 个 PPT backend 自检脚本成功退出，包含 14 组新增范围场景与历史 49 页真实文件回放。
- `npm test`：typecheck 成功，2,808 个测试通过、0 失败、1 项 Linux 专属测试跳过。
- M2 的一项本地 PDF 转换子检查因宿主缺少 matplotlib 跳过，不能计为 PDF 完整验收。本轮没有 UI 修改，不重新声称 UI/打包/远端验收。

新增 `selftest-ppt-input-scope.mjs` 的 14 组场景覆盖：

1. 模型 brief/模板/生成文字不能变成原始输入授权。
2. 来源 SHA 不变时，prompt、来源尾部、知识模式与详细模式变化仍使缓存/计划失效。
3. 局部 instruction 与原始 input 分离。
4. 短 Prompt 与详细来源模式都受到框架约束。
5. 完整长文案尾部、中文/英文、代码缩进、负值表/图与媒体说明进入 critic。
6. 30 页 × 35 槽位长原生稿的尾部不被裁剪。
7. 缺失/伪造 hash、缺页、重复/未知页审查失败。
8. 未完成范围审查的空 findings 报告不能发布。
9. 框架内必要解释可通过，不使用逐字匹配 gate。
10. 无数字的定性越界与虚构具体事实阻止候选。
11. 无模型或旧四数组协议不能通过局部审查。
12. 修改后的候选与旧未审查提案不能应用。
13. 导入输入基线不跟随生成文案变更，原生稿不跳过复审。
14. 越界提案拒绝后项目 revision 与提案存储不变。

兼容测试覆盖完整 API 生成、两轮 critic repair、发布、局部 Proposal、只改标题、翻译、结构 split、暂停/恢复、用户保护、缓存与目标页并发。模型部分为模拟响应；PPTX/来源解析相关自检使用真实文件和生产导出代码，不构成真实 LLM 内容质量实验。

回归中定位并处理了历史 49 页 HTML fixture 的旧来源 ID 错配：旧 c_074 对应结果，而当前解析器的 c_074 已是 PTQ 定义且没有数值证据；旧 segment 611+ 也不存在。回放测试按明确原始来源章节重新绑定 PTQ/QAD/吞吐基准，并保留证据必须锁定、旧浅稿必须被拒绝的断言。这是 fixture 迁移，生产代码没有加入按附近数字猜来源的逻辑。

## 保留的实际边界与后续验收

- 内容范围与事实蕴含依赖语义 critic；模型可能错误声明 complete 或漏报。hash/ID 门禁验证完成协议与版本，不验证每句话的真理。不能宣称零幻觉或真实模型已通过。
- Planner 和逐页 writer 的中间草稿仍可能越界；本轮没有增加独立 outline 语义审查调用。它们共用收紧的 Prompt，最终生成发布必须经过完整范围门禁；局部提案则在持久化前门控。
- 完整上下文增加 token 使用。超长输入若超出模型容量必须失败/未完成，不能静默截断后通过。下一项应实现按页/来源分批的完整审查与覆盖汇总，以保留 fail-closed 属性。
- 原生旧项目若缺少原始输入基线，不能用当前已编辑 deck 追认为原始来源。重新导入内容输入可建立基线；未知事实应由审查保留为未验证。
- 图片内容真实性需要可靠的图像解析/说明或多模态证据；本轮文本 harness 不声称直接验证图片像素内容。
- 人工直接编辑与版本恢复是用户操作，不等同于 agent 自行创作；最终发布仍要求有效审查。
- 建议下一步在真实所选模型上用跨领域同源输入测：越界漏检率、框架内扩展误拦率、必要内容覆盖率、具体事实支撑率、critic 修复收敛率。把正确解释与脱题补充配成反例，尤其包含无数字的新议程、来源内排除项、模板提示注入与长稿尾部。
