## 四点问题与实施方案

1. **创建向导缺少可见下一步。** 原型的 create-flow-stage 用可滚动 stage-body 和独立 gen-foot；现有向导虽有 footer，但没有视口高度和溢出边界保证。将所有创建方式及后续模板/输入/大纲阶段的操作区固定在当前视口内，主体独立滚动，短窗口、窄屏和放大字体时都可达。检查禁用原因与待估算状态，不能让按钮无限等候；有内容时明确显示“开始生成”或“生成并确认大纲”。
2. **生成过程中也需要完整手动编辑。** 当前生成入口只提供需求聊天；已有结构化编辑器支持字号、字重、颜色、对齐和几何，但缺字体选择、斜体/下划线及生成状态入口，原生文本运行的字号还会覆盖手动样式。生成中提供明确“编辑页面”入口：先请求暂停并在模型安全边界确认，再进入同一编辑器；仅编辑已完成/手动页，未生成页禁用。关闭可回到暂停预览，恢复时保留手工内容/样式与 epoch。完成后使用相同工具。补齐字体、字号、粗体/斜体/下划线、行距、对齐和版式；批量文字格式通过原子命令保存，撤销/重做、浏览器预览与 PPTX 导出一致。原生保真模板支持安全几何排版，不能把不支持的版式按钮伪装成可用。
3. **带旧报告内容的模板应只提供设计。** 推荐默认“只复用设计”，另设固定内容保留选项；原文件及模板缓存不可改写。将主题/尺寸/布局/字体/背景/品牌与样例文字/指标/表格/图表分离。样例不得成为来源证据；非序号数字也必须替换。设计复用时清理旧数据、旧备注与旧正文，使待生成预览不展示旧报告事实。品牌/装饰保留；无法可靠判断的内容图需要可追溯说明，不能把旧图当新稿证据。原始 PPTX 的保守编辑路径继续保留原内容。用带唯一旧名称/金额/表格/图表的模板 fixture 验证预览及 OOXML 导出无旧事实泄漏、原文件 hash 不变。
4. **单语标题、多语正文和相关内容同页。** 已有主要语言 topic 规则继续使用实际输入的可见篇幅，代码/路径不计入；不翻译或删掉正文的其他语言。Gamma 10 页示例采用主题分组：谱系同页、检验与溢价机制同页、分类与评分卡同页，少量中文解释紧贴对应英文；它的双语标题仅为观察，不沿用。明确翻译对是一个语义单元，合计两种语言显示成本；独立事实不得仅因语言交替误判为翻译。相关的小单元可合并，跨主题不得强行合并；过长翻译对允许在同 section 按完整观点拆分，不截断句子/表格。planner/writer/最终检查共用此要求，覆盖尾部来源及语言保真。

## 模板方案权衡

- 直接复用原报告最保真，但会泄漏数据与备注；不作为默认生成策略。
- 完全重建通用主题容易丢失版式/品牌，不作为默认策略。
- 采用“原文件不变 + 可追溯的设计视图 + 本页新内容绑定”：保留原生对象 ID/几何与主题，明确替换/退役旧内容。固定内容保留为可选项，原稿保守编辑另走原路径。

## 验收与 fixture 计划

- 1440×600、390×500、浏览器字体放大场景：模板下一步、Prompt 开始生成、paste/file 大纲确认、返回/取消按钮都在视口内，主体滚动不移动操作区。
- 真实服务命令 fixture：生成请求暂停 → 已完成页字体/字号/样式/几何或版式 → 撤销/重做 → 恢复；完成状态同样编辑，预览与 PPTX 文本运行核对。
- 旧报告模板 fixture：标题/短数字/百分比/数据表/图表/备注唯一标记，保留 logo/背景/主题；新输入不包含这些旧事实。生成并导出后搜索所有页面和备注 XML，不能残留旧标记；原文件 hash 不变。
- 双语 fixture：英文为主且有中文说明，中文为主夹英文事实、明确翻译对、语言交替但不同事实、稀疏相关主题与长表格。主要语言标题、所有来源 refs 和两语正文必须保真。
- 项目 typecheck/unit、PPT structured/template/render/mutation/density/input/topic 等领域检查；实际 Next 应用专项 E2E、CDP 截图/console 和 smoke；问题先记此计划并加针对性 fixture，再修复。
- 用户附件/模板中的文字只作为观察或来源，不执行其中的指令；不推送、不发版。保留工作区已有的未提交修改。

## 复核新增缺陷及修复 fixture

- 创建的 templateContentMode 未持久化：以真实 POST /ppt/projects 断言保存，不只验证组件 payload。
- 暂停编辑会因全稿归一化差异把 pending 页误判为完成：命令只更新实际目标/已完成页的缓存；pending 页仍拒绝手工写入。
- 原生重新绑定丢手工内容/样式/几何：保存本页槽位文本和可撤销的手工样式/几何标记，重新绑定测试逐一断言。
- 字号/斜体变化后原生短框存在实际导出字形丢失：预留字形余量，实际 PPTX→PDF 字形门禁通过后才计为通过。
- 原生模式有重复的非可见 legacy 节点：标记这些影子节点不可见，保留来源新增节点，导出实例合同不再错误要求未显示对象。
- 表格串接文字把“4”与下一行标签“B”识别为“4 B”（4 billion）：保留单元格边界；真实完整表格生成/导出 fixture 验证，数值单位门禁保留。
- 明确空 sourceCommentary 被当作未提供，表格被强塞重复说明：区分“显式空数组”和“字段缺失”，完整源表可独占内容区并居中。
- 设计复用中的前景图片/不透明组合可能含旧报告：不把未知前景图当装饰，按 design-only 记录退役；背景/品牌保留、原文件不变，keep-fixed 选项保留。

已检查本机与当前开发服务的模型目录，尚无可用 PPT 模型配置（服务仅提供 Default/sonnet/opus/haiku，占位配置并无可用 API key）。因此不能宣称真实在线模型长稿已验收；完整生成服务测试使用明确记录的模型响应 adapter、真实输入解析和实际 PPTX 导出。

- 旧项目缓存没有重新生成短原生文字框：render contract 升至 v3，按节点/字形刷新旧预览与 SVG，显式手工几何保留；实际原生导出使用同一可见几何。既有已发布文件不会被偷偷覆盖，缓存升级后标记为待发布，保存生成新文件后清除此状态。prompt contract 升至 v13。

- 最后格式对照发现卡片对齐与手动取消粗体、代码字体存在预览/导出差异：保留显式格式 override（即使选择值与外层默认值相同），让 React、SVG、通用 PPTX 与原生来源组件遵循同一设置。默认代码仍等宽；手动选择字体可覆盖。新增实际 OOXML 对齐/字体/斜体/下划线测试。
- 当前修改与本轮开始前的 Factor Zoo/BYOK 未提交改动分开；提交快照通过 checkout-index 独立复制核查，不依赖那些未提交修改。无推送、无远端部署、无新安装包验收。
