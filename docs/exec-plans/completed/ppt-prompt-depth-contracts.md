## 决策日志

- 用户确认：文件/粘贴输入仅依据来源；纯 prompt 可解释通用知识，具体引用与数字需核实。本轮不加入专家知识默认开关、不切换用户选择的模型。
- Gamma 用作内容组织和解释深度参照，不复制其遗漏、未经来源支持的数字或来源自身矛盾。模拟样例不证明真实 LLM 的因果效果。
- 字数是写作建议；实际槽位容量仍是硬约束。保留原生模板几何与人工锁定内容；容量不足应报告、换合适版式或由用户调整页数，不能自动增加页数或截成碎句。
- 来源制作元信息可以留在审查上下文；影响结论的适用条件、限制和证据缺口必须保留。不能规定所有缺口永不显示。
- 保持旧 JSON 输出与项目兼容；新提示词只请求必要文案。完整结构化数据使用有界对象序列化，避免截断 JSON。
- 深度审查需给出页级可操作修复。有界重写最多两轮，每轮最多正文页的 30%；保持暂停、取消、版本与编辑锁守卫，未解决问题保留门禁。

## 设计与验收

1. `routine-runner` 对 PPT 设置独立系统角色；其他 routine 保持现有行为。语言/来源政策/具体页级内容由请求提示词传入。
2. 大纲以实际要讲的主张、解释和证据作为内容承诺；保留现有规划字段兼容旧项目。写作者读取内容承诺、相邻页分工与来源完整表达式、表格关系。
3. 生成、修复与局部优化使用同一语言、来源边界和深度指南。原生槽位文本与非原生结构化文案各只要求一份输出；兼容层派生旧字段。
4. Critic 检查缺失、浅薄、重复、矛盾与无支持内容，给出具体修复；自动修复不覆盖已接受的用户编辑，不绕过最终质量门禁。
5. 验证语言检测、来源约束、旧新 schema、完整来源表格/公式、局部编辑、审查重写及竞态回归；按仓库规则执行 `npm run test`。
6. 真实模型 A/B 须固定用户选定模型、输入与页数，保存响应并渲染检查。环境不可用时明确记录未验证，不把模拟回归当成内容质量验收。
