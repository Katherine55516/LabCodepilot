## 目标

1. 环境配置中存在匹配 `project_root` 的系统且 `name` 非空时，工作台以系统名称作为主展示名称。
2. 文件夹名和路径始终可见，避免同名系统或业务名无法定位实际目录。
3. 无匹配、空名称、接口失败时稳定回退文件夹名，不阻塞项目列表。
4. 系统名称保持实时展示元数据，不写入 `test-workbench.json`，不改变任务、报告、统计和 AI 上下文的项目身份。
5. 项目列表只获取脱敏摘要，不把账号、密码、Token 或完整环境配置加载到该页面。

## 详细设计

### 数据契约

- 新增项目系统摘要类型：`id`、`name`、`project_root`。
- 新增只读摘要 API，服务端从既有 `getAllTestAccountSystems()` 结果映射出最小字段。
- 空 `project_root` 的未绑定系统不返回；同一路径多条记录时沿用既有排序后的首条匹配语义。

### 客户端映射

- 使用既有 `normalizeProjectPath` 构造 `normalized project_root -> system name` 映射。
- 空系统名不进入映射；同一路径保留首条，与 `resolve` / `env-resolve` 当前行为一致。
- 工作台可见时加载摘要；环境抽屉保存后重拉，保证改名即时反映。

### 展示规则（方案 A）

- 已配置：
  - 主标题：系统名称；
  - 次行：文件夹名称；
  - 再次行：完整路径（延续截断 + title 查看全文）。
- 未配置或空名称：
  - 主标题：文件夹名称；
  - 次行：“未配置系统名称”；
  - 再次行：完整路径。
- 同一规则用于项目卡片、项目详情标题、流程头项目标识、报告分组标题和删除项目确认文案。
- 内部仍使用原 `project.name` / `project.path`，AI prompt 和持久化结构不改。
