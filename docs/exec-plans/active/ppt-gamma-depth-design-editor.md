## 发现与改进方案

| 路径 | 当前问题 | 改进 |
|---|---|---|
| 内容深度 | `estimatePageRecommendation` 主要数 token、标题和信号词；公式、代码、例子等材料没有独立容量成本。Gamma 8 卡样例已经显示严重压缩，不能把 8 当作质量目标。 | 以章节、语义 chunk、特殊证据对象及每页可读容量估算；报告内容预算与压缩风险。课程长文以讲授深度为基准，允许超过模板原页数。 |

## 逐层代码审计与本轮落点

### 1. 输入、深度与页数

- `ppt-source.mjs` / `ppt-semantic.mjs` 已将 Markdown 标题、列表、代码、表格和段落切成有来源编号的块；此前 `ppt-planning.mjs` 的页数公式仍以 chunk 总量、标题数量和信号词为主。Gamma 的 ML 教程样本显示此类公式容易把 15 章压为过短的叙事摘要。本轮引入 `sourceCapacityPlan`：按章节聚合语义 chunk，把高优先级材料、公式、代码、表格、图解和案例的占位成本纳入估算。
- 估算中的 2700 是**来源 token 的规划预算**，不是一页上要显示 2700 token。它代表将一段来源提炼为 4–6 个有解释的 point，并为关键证据对象留出页内空间。目标由样例校准为约一章一页，不能把 Gamma 的 8 卡当作授课深度标准。
- `sourcePlanningContext` 曾先列出全局高优先级 chunk，长文的前几个章节可能耗尽细节上下文。本轮改成跨章节轮询，使后面的章节也能进入规划 Prompt。大纲的章节配额与高优先级证据清单在同一次 outline LLM 调用中传入，不加串行模型轮次。
- `PptCreateWizard` 更改页数会调用 `/outline` 重规划。发现编辑器手动增删页时同时把 `analyzedPages` 改为新数量，导致提交时跳过重规划；已修正。用户已手改的标题和重点作为 `outlineSeed` 送回 LLM，供重新分配时保留原意。
- 工作区详情页的旧大纲编辑器原来允许直接增删页后执行 `PATCH /outline → generate`，绕过 LLM。现在页数变化时按钮切换为“按新页数重新规划大纲”，先以用户编辑稿为 seed 重跑规划，再让用户确认生成。
- 发现 `PptWorkspace.analyzeDraft` 返回前端的 outline 只含 section/title/focus/description/children；随后提交会覆盖服务端大纲，丢掉 `chunkRefs`、`refs`、role、证据 ID 和 point 分布。这是内容稀疏及来源错配的直接原因之一。已保留完整大纲字段，前端只编辑可见字段，其余语义约束继续沿用。

### 2. Slide classification 与内容分布

- `inferRole` 原来主要读标题关键词。本轮将视觉意图、来源主题、叙事角色及“定义/机制/案例/度量”等语义一起纳入分类；用户或模型明确给出的 role 仍优先。
- `chooseLayout` 原来在发现任意两个媒体块时直接选择对比版式，且可能在检查第一页之前被媒体块抢占。本轮以封面/结尾、语义角色、视觉意图、真实图表/表格/图片为判据，再由 point 密度决定普通说明或详细讲解；明确设置的 layoutId 保持优先。
- `normalizeBrief` 对长篇课程优先给 detailed 写作深度，同时 `densityContract` 对机制、架构、流程、案例等复杂角色优先给高密度，对普通页保留中密度，避免全稿连续高密度。
- `ppt-content-qa.mjs` 新增章节覆盖率和“章节未映射且未说明取舍”诊断；既有 point 深度、证据可见性、数值忠实度和重复检查继续运行。

### 3. Design engine、styling 与 restyle

- `point-layout.mjs` 原来在详细/高密度页最低缩到 10pt；这与 Gamma 样例 5–7 页的小字拥挤问题相同。现先试单栏、双栏或适合短点的三栏，再降字号，正文下限 14pt（普通页 15pt）；不适配时返回 `overflow` 和建议拆页数，由质量门禁阻止静默裁切。
- `theme.setPalette` 原本只改变四个颜色。新增 `theme.setTokens` 命令，在 deck IR 中保存标题、正文和间距缩放令牌；`render-tree.mjs` 用这些令牌统一构建预览与 PPTX 导出的场景树。对象级手动样式覆盖主题默认值，restyle 不重写正文。模板保真模式继续拒绝全稿主题命令。
- 编辑器新增紧凑/标准/舒展三种全稿文字节奏、当前页 point 数与字号/栏数/溢出提示、每张卡上的 Agent 入口及两张卡之间的插入入口。已有 filmstrip、纵向卡片、对象检查器、局部 AI 预览、版本历史继续沿用。

### 4. 与 Gamma 的关系及必须避免的问题

| Gamma 观察 | 本模块采用 | 避免的样例缺陷 |
|---|---|---|
| Filmstrip + 纵向卡片画布 | 保留双导航，卡片内可直接开启 Agent，卡片间可插页 | 仅有工具栏按钮、用户不知道操作作用到哪页 |
| 模板与块级编辑 | 使用现有结构化 IR、模板字体及原生页保护 | 复制模板装饰但丢弃语义、破坏原生媒体 |
| 自动选择布局与组件 | 分类选择有限版式，几何仍由确定性引擎计算 | 两个组件误判成对比图、空泛装饰图 |
| 按内容自动适配 | 调栏数、调空间并报告溢出 | 用 10pt 小字把 15 章塞进 8 卡 |
| 全稿 styling / 局部 Agent | 主题令牌改全稿视觉；AI patch 改对象/当前页内容 | restyle 重新生成内容，导致事实漂移 |

## 设计边界

- Gamma 样例的 15 章压成 8 卡导致公式、代码及高级主题缺失；本模块参考其**每点具象解释与分布方式**，不复制其过度压缩。
- LLM 决定叙事与内容；章节容量、版式几何、字体下限和溢出是确定性规则。
- 原生 PPTX 保真模式不能随意更换模板几何或全稿主题；保留此保护。
- 用户选定页数为硬参数，估算只给建议与风险，不擅自覆盖用户选择。

## 验收口径

1. 长篇课程的页数建议对章节和公式/代码等重要对象敏感，低于可读范围会标示压缩风险。
2. 用户改页数后，模型收到按新页数重算的章节分配、必须保留对象及省略说明要求。
3. 语义分类不因任意两个组件误选对比；不同角色落到匹配版式。
4. point 排版不低于可读字号，超量时有明确溢出信号，预览与导出共用布局结果。
5. 重设样式只修改令牌，不改正文；编辑器可见当前页容量并支持已有版本/撤销链。
