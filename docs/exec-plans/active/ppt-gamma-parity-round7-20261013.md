### 1. 大纲多次未被接受（B3，Phase 1）

**证据**：汇总两边 `outputs/` 中已保存运行产物里的大纲失败，有两种计数口径。

按失败记录的阶段代码（`stage: outline`）计：`coverage_invalid` 76、`schema_invalid` 36、`timeout` 9、`capacity_invalid` 7、`transport` 4。

按错误信息在产物中出现的次数计：

| 错误信息 | 次数 | 含义 |
|---|---|---|
| `ppt_transport` | 182 | 传输失败 |
| 去向或归属违反展示合同 | 64 | 选取账目违约 |
| `ppt_schema_invalid` | 59 | 结构不合规 |
| `ppt_timeout` | 40 | 超时 |
| 每个单元必须恰好一个去向 | 12 | 漏写去向 |
| `ppt_capacity_invalid` | 11 | 实测放不下 |
| `ppt_truncated_output` | 9 | 输出被截断 |
| 规划元数据不合规 | 8 | 标题/焦点等内部字段超长或语言不符 |
| 关系被拆到正文与备注 / 互译对未同去向 | 6 / 4 | 闭包约束 |

今天在 run17 跑 `gamma.md`（明确 25 页）时，其中一次尝试也因“Every source unit requires exactly one explicit disposition”失败（`full-project-failed.json`），重试后才通过。

**根因**
1. **一次输出要同时满足十几条耦合约束**：页面分组、每个单元恰好一个去向、去向与归属一致、互译对同去向、关系闭包、表格行区间、标题语言、元数据长度……全部在事后校验。修复是局部 delta，修好一条常会破坏另一条，所以不收敛。
2. **把代码已知的决定交给模型**：只有一个合法去向的单元、译文、按策略省略的代码、关系与互译闭包，都可以由代码直接决定，但现在要求模型逐条写对。
3. **输出过大**：整份大纲 + 全量账目一次生成，导致传输错误、超时和截断。
4. **容量问题以拒绝收场**：以前只能拆页或失败（第六轮已改为先压缩）。
5. **确认后仍可能被拒**：确认接口会再跑 `confirmNativeOutlineFit`，可能返回 409，用户已确认的大纲在这里被打回。

**方案：编译而非拒绝**
1. **代码先定账目**：按 `selectionConstraints` 先确定只有一个合法去向的单元（译文 → 备注、省略的代码 → 备注、必须可见 → 正文），并直接应用关系与互译闭包。提示里只列出真正可选的单元（正文 / 摘要 / 备注）。
2. **确定性补全与纠正**：漏写的去向按安全默认补齐（已有页面归属 → 正文或摘要；无归属且允许备注 → 备注；无归属且必须可见 → 同节最近的页）。互相矛盾的写法自动改正（备注单元出现在页面上 → 从页面移除；正文单元无归属 → 挂到同节最近页）。规划元数据超长时由代码在词边界截短（只是内部字段，不上页）。每项修正记入 `outlineCorrections`，在确认页列给用户。
3. **约束输出**：主调用直接使用目前只在修复时用的按批次限定的 schema（ID 枚举、每个 ID 允许的去向）；支持结构化输出的模型开启 JSON schema 模式。
4. **小批次**：沿用第六轮的“按页组一次调用”，每组单独校验、单独重试、单独存检查点；截断时自动续写本组，不重做整份大纲。
5. **容量不拒绝**：先压缩 → 换版式 → 合并 → 最后才拆页（第六轮）。仍有剩余问题时，在确认页提示，不判失败。
6. **只在真正无法继续时失败**：例如原文无法读取、模型不可用。失败时给出明确原因，并只重试失败的页组。

**流程（与原型一致）**
1. 创建流程：读取输入 → 生成大纲（页数由大纲决定，受第六轮的页数预算约束）→ 用户编辑与确认（增删页、合并、改标题、调整页数）→ 冻结执行计划。
2. 用户在确认页的编辑走同一套确定性编译，只给警告，不返回 409。
3. 进入可视编辑器后，严格按冻结的执行计划逐页生成，不再重新规划。写作中的容量问题在页内解决（换版式、压缩进备注），只有用户主动要求时才重新打开大纲。

**验收**
- 20 个带典型模型错误的 fixture（漏 ID、备注单元上页、关系拆分、元数据超长、超容量）全部被接受，并列出修正。
- 真实模型在 Alpha Mining、Factor Zoo、`gamma.md` 上大纲首轮接受率 ≥ 95%，记录耗时。
- 确认后不再出现 409 或重新规划。

### 2. 统一展示合同：主题只用主要语言（B1，Phase 2）

**现状**：主线已按可见篇幅判定主要语言（CJK 计 1、拉丁字母计 0.58，排除代码、路径、URL、图片数据），标题、章节和眉题只用该语言。run17（3141）仍有多处相反规则：
- `compileSkeleton` 在原文双语时强制双语标题（`bilingual_title_missing_language`）；
- 第五轮的双语 eyebrow 档位与 `titlePolicy`、写作提示 `bilingualTitleRule`；
- 第六轮规划提示里“titles and section labels stay bilingual”；
- 目录规划要求每个标签“Keep BOTH English and Chinese”；
- 第五轮的派生封面副题为双语。

**方案**
1. 建立唯一的“展示合同”模块，对外提供 `deckLanguage(project)`，复用主线的主要语言算法。封面标题与副题、页标题、章节、eyebrow、目录标签、结束语都由它决定，规划、写作、模板绑定与最终检查共用这一个判断。
2. 删除或改写上面列出的 run17 双语主题规则。eyebrow 只保留“节号 + 主要语言节名”。
3. 正文可以包含两种语言。默认（`body: primary`）时，互译对中主要语言一侧上页、另一侧进备注。第六轮按“原文一侧”选，改为按 `deckLanguage` 选，保证标题与正文同一种主语言。未成对的另一语言事实照常保留在正文。“正文保留两种语言”选项不变。
4. 以 Gamma 为准统一版面元素：封面（eyebrow / 标题 / 副题）、目录页、章节 eyebrow、卡片式要点、结束页。所有规则写进同一合同，模板绑定只消费合同，不各自决定。

**验收**：中文为主夹英文、英文为主夹中文、各占一半、含代码与图片说明四类 fixture；所有主题字段单语、与主要语言一致；正文双语事实保真；Alpha Mining 实测主要语言并截图。

### 3. 逐页生成的可视编辑器（A2、A7，Phase 3）

**Gamma 观察**（Teardown §5.1、§5.3、C.2）：
- 已完成的卡保留；
- 当前卡出现内联“✦ AI generating”，先出结构和标题，再流式填入段落、要点、代码与图表；
- 后面的卡尚不存在；
- Agent 面板每完成一张卡记一条“Created slide”；
- 用户在生成中就能阅读前几张。

**run17 现状与问题**
- 第五轮给所有未完成页都画了骨架（规划标题 + 模板），看起来是“先铺满整套模板再填内容”，与 Gamma 相反。
- 草稿层 `GenerationSkeleton` 是固定 16:9 且 `overflow-hidden` 的容器，流式文字超过高度后下半部分被裁掉，这是“文字下半部分被遮挡”的直接原因之一。
- 原生文本框高度不留字形余量、SVG 中 foreignObject 缩放，会导致字形和媒体边缘被裁。主线已改为外层 SVG 缩放、文本框预留实际字形高度。
- 流式进度只存在于本地 BYOK 模型任务路径（`pptModelJobs`）；托管路径（`runRoutine`）一次返回全文，没有逐字进度。

**方案**
1. **画布**：只渲染已完成页和当前页；未开始的页不出现在画布上，只在左侧规划列表显示标题和状态。
2. **当前页三步**：先显示该页的版式结构与标题，再按要点顺序流式写入（每个要点先出小标题，再出正文），校验通过后替换为正式渲染。草稿层改为按内容自动增高，不裁剪；媒体占位按真实宽高比显示。
3. **跟随**：默认自动滚动到正在生成的页。用户手动滚动后暂停跟随，并显示“回到当前页”按钮。修复中的页显示“修复中”。
4. **过程日志**：右侧面板逐条记录“已生成第 N 页：标题”，与 Gamma 的“Created slide”一致。
5. **流式**：托管路径（`runRoutine`）同样上报进度，与本地 BYOK 路径共用 transient 草稿通道。不支持流式的模型按要点粒度提交，不伪造打字动画。
6. **遮挡**：采用主线的字形余量与 SVG 方案。增加检查：所有文本框 `scrollHeight ≤ clientHeight`，所有媒体在页面边界内。

**验收**：生成中在三个时刻截图（第 k 页已完成、第 k+1 页流式中、第 k+2 页不存在）；裁剪检查为 0；跟随与“回到当前页”的交互通过；真实模型下可见逐点出现。

### 4. 内容充实不冗余、标题与结束语（A5、A6，Phase 4）

**现状**
- 主线已把“完整来源细节见本页备注”一类可见占位设为硬错误；run17 仍有“完整表见备注”标签。
- 部分页面过薄：例如 10-11 运行里 1.1 节被拆成三页，每页 228–326 显示量。
- 容量拆页产生“（上）/（下）”标题。主线改成续页沿用原标题，但两页同名同样不符合要求。

**方案**
1. **去掉所有可见的备注指引占位**：选行表格不加“完整表见备注”，备注只在备注里。
2. **每页内容区间**：按页面角色给出内容下限与上限（内容页约为实测容量的 55%–95%，或者一个结构 + 至少 2 张卡片）。低于下限时，按顺序：
   - 先把同节已进备注的相关单元提回为摘要卡片（第六轮压缩的反向操作）；
   - 原文不足且策略允许解释时，由写作补充机制、条件或含义；
   - 仍不足则与相邻页合并（第六轮的合并）。
   超过上限时走第六轮的压缩。
3. **去冗余**：复用已有检查（`explanation_restates_source`、复写检测），并新增“卡片复述标题或其他卡片”的检测。
4. **续页标题**：首先尽量不拆页（第六轮的压缩与合并）。确需拆页时，每页按自己内容取标题（例如“评估关卡：数据与样本检验”“评估关卡：成本与容量检验”），禁止“续”“（上）/（下）”和同名页。新增 `duplicate_page_title` 检查。
5. **结束语**：最后一页加“感谢观看”或“Thanks for watching!”（语言跟随 `deckLanguage`）。模板有结束页时使用模板结束页；没有时与结论页同页，不另造一张空页。

**验收**：全稿无占位文案；内容页实测填充率中位数 ≥ 0.6，无低于下限的页；无同名页、无“续/上/下”；结束语语言正确。

### 5. 图片与图表输入、组件自适应位置（A1、A3，Phase 5）

**现状**：主线已统一处理 Prompt、粘贴和文件补充的图片，以及 DOCX 正文/页眉、XLSX 图片与原生图表（经 Office → PDF）、PDF 位图与矢量图、HTML 的 PNG/SVG，并支持 Markdown/HTML 图片引用匹配附件、去重和数量上限。还实现了单组件在标题下方居中。这些只经过 fixture 验证，且不在 3141 上。

**还要补的部分**
1. **Prompt 中的图表**：Prompt 里的数值表格或明确的图表描述（如“销量：Q1 120、Q2 150…”），进入与文件相同的语义索引后，识别为 ChartBlock 候选，生成原生图表，并与来源数字逐一核对。
2. **图片语义**：图片的说明、替代文字和相邻段落一起进入库存，供规划把图片分配到相关页面。必须保留的图片纳入媒体台账（第五轮的守恒门禁）。
3. **组件位置**：在单组件居中之外，加入两组件的平衡规则（例如表格 + 简短说明，按约 2/3 + 1/3 分栏并垂直居中）。新增 `layout_unbalanced` 检查：占用区域的中心偏离内容区中心超过 10%，或单侧留白超过 35% 时，自动重新居中或调整比例（不缩小到字号下限以下）。用户手动调整过的位置优先。

**验收**：六类输入各带已知图片，最终 PPTX 中图片哈希全部出现且带说明；Prompt 贴图与 Prompt 表格图表都可见；单表、单图、表加说明三类页面的居中检查通过。

### 6. 修改生成要求面板、批量操作与原型对照（A4、B2，Phase 6）

**A4 现状**：主线已改为固定标题、主体可滚动、底部固定操作区，并显示初始需求、修改记录和处理结果（短窗口与 390px 宽度验证过），但不在 3141 上。合并后补充：
- 每条消息显示状态（排队 / 已应用 / 失败）；
- 新消息后自动滚到底部；
- 支持 Enter 发送、Shift+Enter 换行。

**B2 复现（3141，1440×900）**
- 勾选后浮动工具栏确实出现（“已选择 2 个项目 / 移至文件夹 / 删除 / 取消选择”），但固定在窗口最底部，离卡片很远，长页面或大窗口里很容易看不到。原型是放在列表上方的内联栏（“已选择 N 个项目 · 移动到文件夹 · 删除 · 取消选择”）。
- 勾选框平时透明（opacity 0），并且被封面上的“AIMATE · PRESENTATION”文字盖住：在勾选框位置点击，命中的是这段文字。实测点击不生效，勾选后又与文字重叠（与截图一致）。

**方案**
1. 勾选框常驻可见（悬停或已有选中时显示），层级高于封面内容；眉题文字右移，避免重叠。
2. 批量操作栏改为列表标题下方的吸顶内联栏，与原型一致；滚动较远时可保留底部浮动栏作为补充。
3. 支持 Esc 取消选择、Shift 点击连续多选；按钮有键盘焦点与可读名称。
4. **原型逐项对照**：对照 `prototype.html` 与实际应用的 PPT 工作区，包括新建、导入、基于上一版更新、搜索、排序（最近编辑 / 最近创建 / 名称 A-Z / 手动排序）、拖动排序、置顶、收藏、卡片菜单、文件夹侧栏与计数、回收站、详情抽屉、创建三步流程、大纲确认页、编辑器工具栏。用同一尺寸截图做差异表，逐项修正。

**验收**：e2e 覆盖勾选 → 内联栏出现 → 移动 / 删除 / 取消；点击命中勾选框；差异表全部关闭并附截图。

### 7. 真实模型端到端验收（Phase 7）

在集成后的单一实例上，用可用的 BYOK 模型生成 Alpha Mining、Factor Zoo 和 `gamma.md` 三份完整稿。逐页对照 Gamma 产物，检查：页数与预算、主题语言、内容密度与冗余、媒体、结束语、生成过程录屏（逐页、逐点、跟随），以及大纲首轮接受情况。结论写回对应 postmortem 文档。fixture 通过不等于真实模型通过，两者分开记录。

## 推荐执行顺序与理由

1. **Phase 0 合并代码线**：不先合并，任何修复都无法在用户使用的实例上验收；两边继续分别改动只会让冲突变大。
2. **Phase 1 大纲一次通过**：大纲不被接受，就生成不了任何页面，是所有生成类问题的上游。
3. **Phase 2 展示合同**：主题语言影响大纲标题、eyebrow、目录和结束语。先定下来，Phase 3–5 不必返工。
4. **Phase 3 逐页可视编辑器**：用户标为“很重要”，且依赖 Phase 1 的冻结执行计划。
5. **Phase 4 内容与标题**：依赖 Phase 2 的语言合同和第六轮的压缩/合并。
6. **Phase 5 图片输入与自适应位置**：主线已实现主体，合并后以补缺和真实验证为主。
7. **Phase 6 界面控件与原型对照**：与 3–5 无依赖，可由另一人并行推进。
8. **Phase 7 真实模型验收**：最后在单一实例上一次性验收全部十点。
