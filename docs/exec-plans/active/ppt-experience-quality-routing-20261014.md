## 1. 结论与证据边界

建议保留已有的结构化编辑器、真实任务进度、来源约束、逐页草稿、字体工具、质量报告和版本机制，优先修复使用阻碍，再统一交互与视觉细节。原型用于确定操作路径、层级和布局参照；其中的模拟生成、简化文件解析和示例数据不作为生产实现标准。

用户已进一步授权按推荐顺序实施本文全部方案。以下原方案保留为验收合同，实际实现与证据见文末执行记录；代码存在不等于产品验收完成。

### 1.2 优先级与取舍

- **P0：可完成任务和内容正确。** 操作按钮可达、加载恢复、真实图片进入内容、暂停草稿保留、无遮挡、来源与人工修改不丢失、正确报告生成状态。
- **P1：流程与编辑效率。** 新建路径简化、作用范围清晰、聊天一致、模板处理、质量等级及多模型编排。
- **P2：视觉一致。** 图标、标签、尺寸和间距；以同视口截图和操作效率决定，不为了像素相同牺牲可用性。

质量等级只改变模型能力、推理和检查投入，不改变用户要求保留的内容、语言、页数、来源规则和发布底线。

### 3.1 推荐创建流程

1. 选择 Prompt、粘贴或导入；从模板中心进入时携带模板。
2. 选择质量等级（默认均衡），确认模板并预览；高级配置按需展开。
3. 输入内容与附件，设置受众、目的、页数、语言与来源规则。上传和提取过程实时反馈。
4. 系统展示建议页数、大纲、主要语言、来源图片分配和需要注意的内容取舍。模型编排预检同时完成。
5. 用户确认计划，冻结内容分配、页数和策略版本，进入逐页生成。
6. 已生成页面立即可读；完成结构化检查、来源检查及导出验证后标记为完成。

“质量等级”和“是否先确认计划”是两个独立维度。第一期保留现有大纲确认流程；后续可增加明确选择的“快速生成”流程，但仍需内部规划和相同正确性检查，不因用户选择快速质量就自动跳过确认。

| E10 / P0 | C：已有冻结范围、候选和版本逻辑 | 保留打开时固定范围；发送前显示页数与标题，用户主动才能重选。生成中的页排队应用，已完成页生成候选；AI 结果以页/对象版本进行比较，冲突不能覆盖人工修改 | 生成继续推进、用户切页、手改文字、跨页指令同时发生时作用范围正确；支持针对一次修改撤销 |
| E11 / P0 | 历史问题包括稀薄内容、备注占位、机械续页与结尾缺失 | 沿用 Round 7 来源、标题和结束页合同，补做真实验收。内容深度按“结论＋必要依据/条件”评估，去重复；主要内容不可仅以“完整表见备注”代替。续页按具体子主题命名，结束语按主要语言呈现 | 短稿、长稿、双语、表格密集稿逐页审阅；不靠固定字数制造冗余，不用无来源事实扩写，尊重用户锁定标题和页数 |
| E12 / P1 | C：已有质量阻塞、诊断和修复记录，状态信息较技术化 | 默认显示“需要处理什么、影响哪页、可采取什么操作”；模型、校验代码、JSON 等放进详情。草稿可检查，完成状态必须与已验证发布版本一致 | 不出现“100% 完成”但没有可用成品；来源本身矛盾时说明原因，不靠反复换模型消除警报 |

### 4.1 生成与人工编辑的协作规则

- 模型写入先落草稿，完成一个有效组件后提交结构化对象；未完成 JSON 不直接成为可编辑对象。
- 已完成页允许人工修改；修改写入独立的用户覆盖层或等价版本化操作，后续模型写作不能覆盖它。
- 暂停立即停止调度新任务；已经发出的请求可取消则取消，不能取消则允许收取结果到缓冲区，暂停期间不自动覆盖画布。
- 页面并发生成与画布展示顺序分离：后台允许有限并发，画布按文档顺序提交；已完成的后页可以在计划列表显示就绪状态。
- 用户滚动查看前页后停止自动跟随，并提供“回到正在生成”；恢复和刷新保留当前位置。

## 6. 用户选择质量等级，系统分配模型

### 6.1 用户界面与等级合同

创建时默认“均衡”，提供三个单选卡片。用户能看到适用场景、相对速度和资源消耗；具体模型放在“查看模型分工”中。没有价格数据时只显示估算 token/调用范围，不编造金额或精确完成时间。

| 维度 | 快速 | 均衡（默认） | 严谨 |
|---|---|---|---|
| 用户说明 | 用较少投入快速形成可检查初稿 | 兼顾内容质量、速度与成本 | 用于复杂材料与重要交付，投入更深入的规划和检查 |
| 全局规划 | 简单材料由快速/标准规划模型处理，复杂材料自动升级 | 标准规划模型；复杂材料使用强规划模型 | 优先强规划模型及支持的较深推理 |
| 简单页面 | 快速写作模型 | 快速写作模型 | 快速或标准模型；高等级不要求所有简单任务都用最强模型 |
| 中等页面 | 标准写作模型，失败有限升级 | 标准写作模型 | 强写作模型或更充分推理 |
| 复杂页面 | 直接强写作模型；预算不足时明确提示 | 直接强写作模型 | 强写作模型，并增加独立语义检查 |
| 视觉理解 | 仅处理必须理解的图片/扫描页 | 按实际需要使用视觉模型 | 对复杂来源图表和关键页面增加视觉交叉检查 |
| 图片生成 | 快速图片档位，仍受用户图片策略限制 | 标准图片档位 | 较高质量图片档位；无图/仅原图策略不生成配图 |
| 语义审查 | 全文分批基础来源审查；复杂页使用强审查模型 | 全文来源与覆盖审查，重点页强审查 | 全文强审查，关键数字/公式/视觉页增加独立检查 |
| 自动质量修复预算（初始建议） | 每个失败任务最多 1 轮修复 | 最多 2 轮 | 最多 2 轮；仍不通过则明确保留阻塞，避免无限修复 |
| 布局与导出检查 | 全部执行 | 全部执行 | 全部执行 |

共同底线：来源数字与单位正确、必要内容和要求保留的图片不丢失、正文/标题语言遵守设置、无实际裁切遮挡、人工编辑不被覆盖、导出可打开。任何档位都不能通过降低检查标准获得“完成”。“严谨”是更高投入，不承诺事实绝对正确。

质量等级与内容详细程度互不替代。例如“快速＋完整内容”仍须保留完整内容；“严谨＋概览”不应擅自扩成全文。现有项目保留原等级快照；用户改等级时，只影响明确选择的后续任务或重试，不静默重跑已完成页面。

### 6.2 模型角色与任务边界

| 角色 | 任务与输入 | 产出 | 默认执行者/升级条件 |
|---|---|---|---|
| `source_parser` | 文件解包、文字/图片/表格/代码提取、来源位置 | 稳定来源 ID、资源清单、原始数值与单位 | 程序；扫描/图文关系交给 `vision_reader` |
| `source_organizer` | 语言识别、章节分组、互译关系和重复候选 | 来源结构与不确定项 | 程序＋快速文本模型；复杂关系升级标准模型，不能改写原始来源 |
| `planner` | 全局目标、来源索引、页数和版式容量 | 叙事顺序、每页主题、来源归属与展示方式 | 标准/强模型；确定性编译器补齐已知规则并验证 |
| `writer_fast` | 冻结页合同、少量来源、标准结构 | 简单介绍/列表/结论页内容 | 快速文本模型 |
| `writer_standard` | 中等复杂来源、常规比较与解释 | 页面组件与有依据的解释 | 标准文本模型 |
| `writer_reasoning` | 公式、代码、复杂条件、多来源或跨页关系 | 复杂页面内容及引用映射 | 强推理文本模型 |
| `vision_reader` | 图片、扫描页、图表局部及其上下文 | 结构化识别、置信/不确定信息、来源关联 | 已验证支持图像输入的视觉模型；不确定数值保留待核对 |
| `image_creator` | 页面目的、主题样式、用户图片规则 | 新图片资产与生成记录 | 专用生图模型，与文本模型池独立 |
| `layout_engine` | 组件、字体、页面尺寸、固定/用户对象 | 排版几何、碰撞/越界结果 | 确定性程序；模型只提供候选结构 |
| `critic` | 来源证据、实际可见内容、备注和冻结合同 | 每项发现、证据、严重性、影响页、修复类型 | 独立审查调用；复杂页优先使用与写作者不同的已评估模型 |
| `repair` | 具体失败项及最小受影响范围 | 可验证的局部补丁 | 几何→程序；语义→对应文本角色；图像→视觉路径，不统一全稿重写 |
| `export_validator` | 当前发布候选的 PPTX/PDF 与渲染 | 文件完整性、字体/边界/媒体验证报告 | 程序＋必要的视觉审查；结果绑定实际文件 hash |

“独立审查”至少要求独立调用、独立来源证据和明确判定标准；仅换提示词不能宣称多模型交叉验证。只有一个可用模型时可采用不同角色的独立调用，但运行详情必须注明同模型审查，不能伪装成多个模型。

### 6.3 按页难度路由

先检查能力与硬触发，再做复杂度分级。首版规则可解释、可记录，不用模型自己声称“这个任务简单”作为唯一依据。

| 等级 | 典型条件 | 例子 | 路由 |
|---|---|---|---|
| 简单 | 单一来源、清楚的主题、少量同类要点、无公式/代码推导 | 团队介绍、已有结论摘要、简单日程 | 快速写作模型 |
| 中等 | 多组信息、常规比较、解释性段落、需要双语配对 | 方法优缺点、双语概念比较 | 标准模型，失败可升级 |
| 复杂 | 公式与条件、代码语义、多来源结论、大表语义拆分、跨页依赖、复杂图文关联 | 因子构建流程、模型假设与公式、研究结果比较 | 直接强模型；必要时先视觉识别 |
| 待澄清/来源异常 | 来源互相矛盾、关键图表无法读取、缺少必要数据 | 分组乘积与原文组合数不一致 | 报告来源问题，保留证据；更换模型不能替用户改事实 |

长度仅作为辅助信号；短公式也可能复杂，长但规则清楚的清单不一定需要强模型。程序负责表格拆分范围、逐项覆盖与重复检测，避免让强模型重新生成已知数据。

模型返回无效结构时，先执行安全的格式修复和已有大纲编译；内容语义失败才升级写作模型。不要因图片加载慢、渲染器失败或模板坐标问题而升级文本模型。

### 6.4 模型目录、选择顺序与配置

复用现有 BYOK/托管服务商配置，新增角色能力目录，保存 `providerRef` 和真实模型 ID；不把密钥复制到项目、任务日志或文档。

目录至少包含：文本/视觉/生图能力、结构化输出支持、流式支持、上下文和输出限制、可用推理参数、限流/并发、已验证协议、价格信息来源与更新时间、最近健康状态，以及本地评测结果。

选择顺序：账号与配置可用 → 数据发送范围允许 → 模态/上下文/schema 等能力满足 → 角色质量基线达标 → 当前等级与预算 → 健康和限流 → 同等质量下较低延迟/成本。不能只靠模型名称、价格或服务商营销名称决定能力。

初期具体模型映射应以用户已配置的可用模型为准：标记为快速池、标准池、强推理池、视觉池、生图池和审查池；通过固定评测集后再成为该角色默认值。未完成评测的模型可供高级用户选择，但必须标为未验证，不写入“推荐默认”。

若没有满足某角色的模型，在创建预检中说明缺失项。用户可配置模型或选择可用策略；不能将不支持视觉的文本模型当作视觉回退，也不能静默跨到未配置的服务商。仅单个模型时显示“当前使用单模型兼任多个角色”。

## 7. 基于现有任务系统的具体实现

### 7.1 现有基础与缺口

当前 `ppt-model-jobs.mjs` 已携带 stage、schema、输出预算、超时和流式进度；本地队列有并发限制。BYOK 请求主要继承 `project.configId` / `project.model`，并未按角色和难度选择模型。`ppt-desktop-model-worker.ts` 还有按模型名称及阶段关闭推理的逻辑，需要迁移为经过验证的能力适配与任务策略；不能直接对所有模型开启深推理造成超时回归。

保留当前 PPT API、模型桥、草稿存储、结构化命令、来源检查和导出接口，在它们之间增加路由层；避免形成第二套内容生成流水线。

### 7.2 原始数据结构提案（实际字段与实现见第10节）

```ts
type QualityLevel = 'fast' | 'balanced' | 'rigorous';
type ModelRef = { providerRef: string; modelId: string };

type PptExecutionPolicy = {
  version: 1;
  qualityLevel: QualityLevel;
  routingPolicyVersion: string;
  modelCatalogVersion: string;
  roleRoutes: Record<string, {
    primary: ModelRef;
    fallbacks: ModelRef[];
    reasoningEffort?: string; // 仅在该适配器验证支持时发送
  }>;
  budget: {
    maxEstimatedCost?: number;
    currency?: string;
    maxInputTokens?: number;
    maxOutputTokens?: number;
    maxAttemptsPerTask: number;
  };
};

type PptTaskContract = {
  taskId: string;
  runId: string;
  role: string;
  stage: string;
  slideIds: string[];
  objectIds: string[];
  baseRevision: number;
  sourceHash: string;
  outlineHash: string;
  sourceRefs: string[];
  requiredFacts: string[];
  requiredAssetIds: string[];
  languageContract: unknown;
  layoutBudget: unknown;
  userLocks: unknown;
  complexity: 'simple' | 'medium' | 'complex';
  complexityReasons: string[];
  executionPolicyVersion: string;
};
```

以上是接口草案；落地时 `unknown` 必须复用既有类型或补充有版本的 schema。既有 `generationPolicy` 继续负责内容/来源/语言，新增 `executionPolicy` 负责模型投入，避免混在一个开关中。

每次调用另存不可变执行记录：任务及尝试 ID、实际模型、路由理由、回退/升级理由、输入和输出 hash、schema/提示模板版本、排队/首字/完成耗时、实际 usage、成本是否估算、失败分类和检查结果。不保存隐藏推理内容；普通用户查看简明进度，高级详情才展示执行轨迹。

### 7.3 上下文交接与并发

全局规划接收来源索引和必要全文分组；单页写作接收该页来源、全局术语/风格约束、邻页主题摘要及冻结合同。不要给每页重复发送整份报告、完整历史和所有模板 XML。复杂关系页可增加明确相关来源，不能任意扩大内容范围。

每页输出必须包含组件、来源映射、必要事实和媒体处置。已知表格数据、代码片段或图片由程序直接绑定，模型只写需要解释的部分。

大纲确认后允许有限页面并发，受账号、服务商及全局并发共同限制；初期沿用现有总并发上限作为基线，实测后调整。媒体可独立处理，但只在资产完整且验证通过时提交。提交使用页/对象版本检查，避免多任务互相覆盖。

### 7.4 失败分类、回退与预算

| 失败类型 | 处理 |
|---|---|
| 429、暂时网络故障、明确可重试的 5xx | 尊重 Retry-After，退避；在用户已配置且允许的池内切换。默认最多 2 次传输重试，计入统一调用上限 |
| 401/403、模型不存在、余额或配置问题 | 熔断相应配置，显示可操作原因；不反复重试同一凭据 |
| schema 不支持 | 使用该适配器已验证的 JSON 降级方式，服务端验证仍执行；不能无限切模型 |
| 内容遗漏、错误解释、条件丢失 | 保留失败证据，按质量等级的修复预算升级受影响页或对象 |
| 布局越界、字体/图片问题 | 交给布局/字体/媒体路径，语义确需精简时才请求文本模型 |
| 来源矛盾、用户锁定与页数/容量无法同时满足 | 展示冲突与处理选项；禁止偷偷更改原文、删必要事实或降低门禁 |
| 请求结果未知、响应交付失败 | 先查任务/提供方状态和检查点；不能把任意写请求直接重放。记录可能的重复计费不确定性 |

统一尝试上限包含 schema 回退、传输重试、质量修复与升级，初始建议每个语义任务至多 5 次实际模型调用；任何等级都受全局预算和该上限约束，避免各层分别重试造成调用乘法。候选无实质改善时提前停止。

开始前估算调用与资源范围；执行前预留预算，完成后按可用 usage 结算。预算不足则在任务边界暂停新调度，保留可读草稿，提供提高上限或调整未执行任务等级的选项，不静默降级。未知价格标记未知，不能当作零成本。

### 7.5 检查点、缓存与版本

- 为来源解析、语言关系、大纲、单页写作、图片、审查和导出建立可恢复检查点；复用现有存储扩展，模型桥重启导致在途失败时从任务边界恢复。
- 调用层使用逻辑任务 ID，尝试层使用独立 attempt ID；过期 lease/旧 run 的进度和结果不得写入当前草稿。
- 缓存键包含来源/附件 hash、来源范围、用户合同、模型与参数、提示/schema 版本、模板/字体、人工修改版本。任何相关输入改变都应使对应缓存失效。
- 来源提取可跨质量等级复用；更换等级不自动重算整份输入。审查必须针对当前实际可见内容，旧版本通过结果不能用于新内容。
- 旧项目缺少策略时映射为 `legacy_single_model` 并保留原模型；用户主动选择等级后创建新策略版本，不静默迁移历史任务。

## 9. 验收与模型评测方案

### 9.1 UI 与功能矩阵

| 组别 | 必测组合 | 判定证据 |
|---|---|---|
| 工作区 | 网格/列表、搜索/收藏/文件夹、长标题/标签、选中后过滤、删除恢复、接口失败 | 同视口截图、键盘/鼠标操作、范围与计数一致性 |
| 创建 | Prompt、粘贴、导入、模板入口、上一版更新；短窗口与 200% 缩放 | 主按钮始终可达、输入保留、明确大纲确认、无重复项目 |
| 图片与图表 | PNG/JPG 引用、图片＋文本剪贴板、PDF/DOCX/XLSX/HTML 内图、扫描页、数值图表 | 源资产→组件→页面→导出映射及实际图像/数字比对 |
| 模板 | 系统模板、旧报告 PPTX、含 logo/旧表格/背景文字的模板 | 旧报告无污染、固定内容正确保留、兼容限制明确 |
| 生成编辑 | 首页流式、前页查看、暂停/恢复、刷新、断线、并发返回乱序、手改后 AI 回写 | 连续录屏、草稿/版本记录、无内容倒退或覆盖 |
| 格式与排版 | 中英字体、斜体下划线、表/图居中、图注、长表、圆形裁剪、公式代码 | 浏览器逐页检查＋实际 PPTX/PDF 渲染；不能只检查 DOM 边界 |
| 聊天 | 长历史、长指令、范围变化、输入法、重试、版本冲突、局部撤销 | 消息持久化、固定输入按钮、一次意图一次应用、无越界修改 |
| 模型路由 | 3 等级×简单/中等/复杂页；单模型、无视觉、限流、鉴权失败、预算不足 | 实际执行模型与策略一致；回退可追踪、调用上限有效、恢复幂等 |

视觉验收覆盖桌面主尺寸、短窗口、移动宽度与缩放。不同页面类型逐页审阅，不能仅看封面或自动文本边界就宣布无遮挡。按钮存在、测试文件存在、状态字段为 completed 都不单独构成验收通过。

### 9.2 真实同源基准

使用固定来源、同一模板、同一内容/语言合同和同一页数设置，对比“当前单模型基线、快速、均衡、严谨”。初始建议至少 12 个独立样本：短业务稿 3、长双语稿 3、公式/代码稿 2、表格/图片稿 2、旧报告模板 2；来源异常样本另作为负向集。先试跑再按方差增加重复次数，至少对代表性样本重复 3 次，不能以一次成功证明稳定性。

Alpha Mining、`gamma.md` 及此前 Factor Zoo 案例可沿用，必须记录来源 hash。原文存在已知矛盾的 Factor Zoo 应作为来源异常测试；未经用户明确决定不得修改原始文件，也不能将被正确拦截的案例计为正向成品通过。

记录：

- 全局规划耗时、首张可读页时间、每页生成/排版/检查时间、总耗时及队列等待；样本不足时不宣传稳定的 p95。
- 来源覆盖、必要事实/图片保留、数字/公式错误、主题语言、双语对应、重复内容、正文密度与阅读性。
- 字体/遮挡/布局、图片角色、模板旧内容残留，以及实际可编辑 PPTX/PDF 的逐页表现。
- 首轮接受、质量修复、模型升级、失败类别、用户需要手工修正的数量。
- 每阶段实际模型和 token；有可靠价格时计算成本，否则列用量和估算假设；所有重试计入总成本。

共同交付条件：所有正向验收样本无未解决的关键事实/媒体丢失、无实际裁切遮挡、无人工编辑丢失、最终文件可打开。负向样本应被正确识别并可恢复处理。均衡等级相对单模型基线的成本/耗时目标须在基线测量后设定，不能预先承诺固定降幅；严谨等级若没有可测的质量收益，应调整路由而非只增加调用。

评测采用来源证据＋确定性检查＋人工逐页复核；模型审查只是其中一层。测试必须保留失败记录，禁止缩小输入、删掉困难页、降低断言或修改来源来获得通过。

### 9.3 工程检查
